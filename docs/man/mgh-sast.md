# /mgh-sast 使用说明(人话版)

> 受众:人类。本文件是说给你听的通俗说明;命令的完整技术定义在命令壳 `.md` 里,给 AI 读。

## 这命令做什么

对代码仓库做一次**静态安全扫描**:不运行你的代码,由 AI 逐个文件阅读和分析,找出潜在的安全
漏洞(注入、越权、敏感数据泄露这类问题),最后给出一份按严重程度排序的报告。

流程分九步(调查 → 建威胁模型 → 拆分代码 → 逐块深挖 → 过滤 → 复核 → 去重 → 关联成攻击链 →
出报告)。其中读代码、判断风险的步骤由 AI 完成;计数、去重、生成报告文件这类机械步骤由内置
脚本完成,不靠 AI 数数。

支持整个仓库扫、只扫最近改动(对比某个 git 基线)、只扫某个目录或包,也支持批量扫多个仓库。

## 会动你项目里的哪些文件

- **新建** `<你的仓库>/security-scan/` 目录,所有扫描过程和结果都放在里面(建议把它加进
  `.gitignore`,脚本会自己写一份)。
- **不改你项目的任何一行代码。**扫描是只读的。
- 运行期间,AI 会在内存里临时整理材料,但不往 `security-scan/` 之外的地方写东西。

## 产出什么

都在 `<你的仓库>/security-scan/` 下:

| 文件 | 是什么 |
|---|---|
| `report.md` | 人读的报告:发现的问题、可被串成攻击链的组合、被过滤掉的低价值发现的附注 |
| `report.sarif` | 机器可读的标准格式报告,可导入告警平台 |
| `run_manifest.json` | 本次运行的元信息(版本、模型、耗时、扫描范围) |

## 风险与边界(诚实披露)

- **结果是「待复核的候选」,不是确认的漏洞。**AI 会误报,也会漏报。每条发现都需要人判断。
- 每次运行结果不完全一样(AI 判断有随机性);两次扫描发现数量不同是正常的。
- 代码之间的调用关系是靠文本分析得来的,看不懂反射、依赖注入、框架自动路由(比如 Spring
  的 `@RequestMapping`、Feign)。没看懂的部分会在报告里明确列出来,不会假装看懂了。
- 大文件会被切片处理;超大任务可以中断后断点续跑(重跑同一命令即可,已完成的单元自动跳过)。
- 需要联网吗?不需要装任何东西,脚本只用 Python 标准库。AI 分析消耗的是你宿主 AI 的额度。
