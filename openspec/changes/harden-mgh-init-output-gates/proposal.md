# harden-mgh-init-output-gates

> **人话序**:2026-10-23 在一个 243 万行的真实企业仓上完整跑了一轮 mgh-init:36 小时无人
> 值守、零失败、过程文件 JSON 全部可解析、规则文件 258 个锚点 257 个真实存在——流程与
> 结构都过硬。但事后审计发现一个被掩盖的大问题:中间清单里有 691 条安全控制,最终规则
> 文件里能对上证据的只有 45 条(6.5%),而且没有任何一道关卡发现它,消费方也无从知道
> "少了什么"。根子是同一类:模型的每次写入都不可靠(有批次自报完成但记录文件消失、有包
> 会话私自写发明出来的账本文件、写入时想校验 JSON 语法又被守卫拦掉),而流水线从头到尾
> 没有做"上下游对账"。本 change 加三道确定性的闸门:①装配时逐条对账"清单里的控制必须
> 出现在规则里",没对上就拒绝写盘并把缺口披露给使用规则的 agent;②清单里的证据锚点必须
> 真能解析到仓库里的真实文件(文件在、行号在、类名方法名在);③"完成标记"必须配套记录
> 文件才算完成(缺记录就重派),并给子代理一条合法的 JSON 语法校验通道、明文禁止私写
> 账本文件。三道闸全部是零大模型调用确定性检查,弱模型强模型都受益。

## Why

真实大仓首跑(2026-10-23,36h 无人值守)的产物审计与两个子代理会话的取证,把"流程稳定、
产物质量无人对账"的断层钉死了:

1. **覆盖缺口无门可拦**:T3 出规则的既有契约本来就要求"一条规则对应一个有锚点的控制",
   但实测 inventory 691 条控制中只有 45 条(6.5%)的证据能在对应类别规则文件里找到、全部
   规则文件锚点引用合计仅 ~258;没有任何确定性检查做"清单 ↔ 规则"对账,装配照常通过,
   消费方拿到的索引块不知道自己只覆盖了零头。
2. **证据锚点无存在性校验**:T1→T2 闸门与装配 lint 都只查"字段非空/枚举合法";实测
   inventory 证据锚点约三分之二解析不到仓库文件(路径形态与真伪构成待门部署后自动揭示),
   规则文件锚点也有符号级漂移(257/258)。
3. **完成标记 ≠ 产物在**:scout 有批次"会话里明确写入成功并摸了 done 标记,记录文件随后
   消失",被"1052/1052 done"的表面数字掩盖;done 标记是子代理自己写的,没有"标记必须
   配套记录文件"的对账,丢了就是静默覆盖损失。同类:t1 有 52/115 个包会话私自写了设计
   上不存在的"包级账本"文件。
4. **写入时零语法校验成常态**:子代理尝试 `python3 -c`/`node -e` 校验 JSON 被运行域守卫
   按设计拦截后退化为 `wc -c`/`ls` 存在性检查——语法错误只能等下游闸门救,而下游(见
   1、2)恰恰没有对账。

这四条是同一根因(执行保真不可靠 + 管线零对账)在四个位置的投影;三道确定性闸门把它们
一次收口。守卫对 heredoc 内容误伤的修复(已致记录内容被改写)维护者另行立项,不在本
change。

## What Changes

- **inventory↔规则对账门 + 缺口披露**(rules-emission):`assemble_rules.py --check` 扩展
  ——inventory 中每条带证据的控制,其证据路径(整路径或文件名级)MUST 出现在对应类别
  规则文件文本中;未呈现 → 不写盘、退出码 2、stderr 按 category 计数 + 首 N 控制名;
  通过时受管块追加一行覆盖披露(已入规则 N/总数 M)。提供 `--accept-coverage-gaps` 显式
  逃生门(仍写披露 + 记边界)。
- **证据锚点存在性门**(control-discovery):`validate_inventory.py` 扩展——每条 evidence
  token(三种形态:`path:line`、`path::类.方法`、`path:类.方法`)按解析阶梯(精确 →
  大小写不敏感 → 唯一文件名回退)找到文件,行号在范围、类名/方法名在文件文本中在场;
  违规分类计数 + 示例,任一违规退出码 2。
- **marker↔记录对账**(control-discovery):枚举器(`list_scout_batches`/`list_clusters`)
  把"done 标记在而记录文件缺席"的单元判回 pending(自然重派);`resume_state --check`
  将此类记为违例;按设计 marker-only 的单元(pack 派发标记、t3 规则产物单元、t2 终结
  标记)豁免。
- **合法 JSON 校验通道 + 禁自发账本**(control-discovery):五个 tier 任务模板增加"写入
  checkpoint 后以 `py -m json.tool <路径>` 做只读语法校验,失败即按单元失败处理"的指令;
  守卫解释器面确保该只读形态放行(现状已放行则零改动,apply 期核实);t1 Form B 明文
  禁止写包级账本/清单文件。

## Capabilities

### New Capabilities

(无)

### Modified Capabilities

- `control-discovery`:新增三个 requirement——证据锚点存在性门(T2 边界)、done 标记必须
  配套记录文件(marker↔记录对账)、tier 任务模板的合法 JSON 校验通道与禁自发账本。
- `rules-emission`:新增一个 requirement——装配边界的清单↔规则覆盖对账门与缺口披露
  (含 claude 面、逃生门与幂等披露行)。

## Impact

- **改动面**:`core/scripts/validate_inventory.py`、`assemble_rules.py`、
  `list_scout_batches.py`、`list_clusters.py`、`resume_state.py`(校验/对账/枚举语义)+
  新增锚点解析共享小模块(兄弟导入,R5.3a)+ 五个 `core/prompts/fragments/fanout/*-task.md`
  模板(+校验指令、t1 禁账本一行)+ 对应契约文件与 t3/done stage fragment 的指针更新;
  三面命令壳(opencode/claude/dsh)调用行不变,新增失败形态在 fragment 披露。
- **既有行为**:全部门默认 fail-loud;`--accept-coverage-gaps` 是唯一放宽开关且必披露。
  首次部署在既有真实仓产物上预期大量触发(覆盖 45/691、锚点约 2/3 解析失败)——这是
  设计意图:让被掩盖的缺口可见,而非回归。
- **预算**:模板每处 +2–3 行,预算 lint 复核;零新增依赖(纯标准库);VERSION bump。
- **不做**:守卫 heredoc 误伤修复(维护者另立);证据引文一致性(evidence_snippet 与源码
  比对,当前 inventory 证据为纯字符串无片段,留待有片段数据后);checkpoint 换带 schema
  工具提交(真实管线 JSON 零坏,已降级)。
