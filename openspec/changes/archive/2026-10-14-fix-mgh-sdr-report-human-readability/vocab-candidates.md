> 方法：三个并行评审子代理分域通读（sdr 域渲染层/契约/提示词；init/ut-init 域装配脚本与

## 1. 定稿：核心闭集（全工具族通用，10 词条）

判定标准：跨域出现（≥2 个命令域）+ 词形稳定 + 误伤可接受。词条带「人话替身」字段——
改写确定性文案和读者评审都用它当翻译指引。

| 词条 | 人话替身（改写方向） | 备注 |
| --- | --- | --- |
| 投影 | 「按预算截取/只带了一部分」 | 子串匹配自动覆盖「基线投影」；DB「投影/物化视图」撞车可接受（告警面软） |
| 切片 | 「从 diff 里切出的一小份只读文件」 | 日常词（数据切片），安全报告语境基本无撞车 |
| hunk | 「一段改动（diff 里的连续行块）」 | git 行话，初级开发未必识 |
| 扇出 | 「一项大任务拆成多个并行子任务」 | 电子学「扇出系数」撞车中等，报告语境无碍 |
| 物化 | 「落成文件/生成实际文件」 | 借自 DB「物化视图」；一般开发需转述 |
| 待办壳 | 「编排器看到的待跑任务清单条目」 | 零外部撞车，纯内部生造词 |
| facet | 「子类/细项」 | 英文黑话未翻译 |
| 闭集 | 「固定清单/固定枚举」 | 数学词；「按闭集排除」→「按固定清单排除」 |
| vvah | （删除/改述为「原项目」） | 上游工具代号，已实际泄漏进 SAST 报告页脚（purity 第 8 类同款） |
| vvaharness | （删除/改述为「原上游项目」） | 同上 |

## 2. 定稿：域补充词（sdr 激活；其余域预置待登记）

时激活，未登记域仅作数据预置（守卫不扫未登记表面，零副作用）。

## 3. 候选池（评审发现但**不收**，理由存档）

- **报告结构章节名**（简报表、诚实边界、无问题单元、章节一/二/三）：工具腔但语义可读；
  「诚实边界」被 `--check` 硬编码断言、全套报告锚依赖——属信息架构决策，留给报告改版
  change，词表不动它。
- **工程通用词**（熔断、退避、降级、兜底、幂等、透传、落盘、真相源、终态、检查点、波次、
  闸门、白名单、内省、消毒、编排器、运行域、哨兵单词、簇单词、基线单词、单元单词、存量
  单词、确定性）：中文工程圈/安全圈通用或半通用，子串禁必误伤；人类面出现时靠读者评审
  兜底建议。
- **阶段代号**（T1/T2/T3/T4、scout、a1–a5、s1–s9、P0/P1、r1–r2）：纯内部语义，但装配层
  的既有纯净性检查**有意**排除裸代号（历史决议：裸词非确定性可测、误伤面大）；与该立场
  保持一致，不进强守卫，候选池留档。
- **高频但高危**（扫描器单词、锚定单词、哨兵单词、越界读撞 OOB、泄漏撞 data leak）：
  同形撞车强，只按 §4 精确词形/短语收。

## 4. 同形词守则（词表维护的硬规矩）

锚族案例是全表的红灯样本：「锚点」（证据锚点，`文件:行`/`文件::类.方法` 格式的出处指针）
是产品概念，sra 里「锚定到需求条目」还是正常动词；只有 sdr 的「路由锚/向上锚定/锚定
单元」是分组算法词。因此：

- **同形不同义的词按域归组收精确词形，NEVER 收单词做子串禁**（「锚定」「基线」「单元」
  「哨兵」「存量」「簇」全部如此处理）；
- 新词条录入时 MUST 检查它在其他域和安全通用语境的撞车可能，把撞车写进词条备注；
- 核心集只收「子串匹配即可安全命中」的词；需要排除合法组合的词降级为域补充的精确词形。

## 6. 增长流程（采集后的常态机制）

读者评审建议 + 维护者人工发现 → 维护者确认（防评审误报直接污染词表）→ 向
`human_face_vocab.py` 加一行（含域归属与人话替身）→ 同步更新内容锚测试 → 该词即被
确定性文案守卫与末步告警两面拦截。整表重扫不常规进行；若未来某域接入时需要，按本文件
§1–§2 的方法对该域再做一次分域评审即可。
