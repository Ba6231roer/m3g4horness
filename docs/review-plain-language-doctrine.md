# 文档可读性分析:模型写作「口音」问题与双层产物制度(评审稿)

> 面向维护者。来源 = 2026-08-17 `/opsx:explore` 会话探讨(主题:大模型升级后中文文档越来越难懂的成因与对策)。
> 状态 = **评审稿**:维护者新会话评审本文,通过后再发起 `/opsx:propose`(change 暂名 `add-plain-language-doctrine`)。
> 本文自含全部探讨结论,不依赖原会话;证据均给文件路径,可独立复核。

---

## 1. TL;DR

1. **问题成立**:近几代模型升级(包括但不限于GLM5.2，GLM5.3)后,本仓全部产物——spec 工件、AGENTS.md、分发提示词、
   终端报告——出现系统性的「难懂」:英文原词当零件、名词堆叠等式句、生造压缩词、写给「共享全部
   上下文的自己」。人类读者要靠猜才能读。
2. **成因 = 模型层口音 + 项目层放大器**:模型层(训练偏代码 + 省 token → 学出一套自用语言)不可控;
   项目层(R3 明文「面向 AI 阅读」、R5.5 措辞纪律外溢、agent 写给 agent 的自消费链路、术语无词典)
   **全部可控**。
3. **解药已在本仓存在**:`docs/r5-plain-language.md` 是全仓唯一人类可顺畅阅读的文档——证明模型
   被明确要求时完全写得出人话。缺的是要求,不是能力。
4. **方案 = 双层产物制度(受众按文件分离)**:人类面(说明书 / 词典 / proposal 人话序 / 终端报告)
   强制人话;agent 操作面(NEVER 链、flag 表、纪律段)**字节不动**。
5. **两大担忧已答复**(评审重点,见 §5/§6):改写对执行效果的影响结构性归零(必做项零接触已验证
   提示词面);token 增量不走任何每轮上下文路径、不走子 agent 受限预算,唯一每轮路径(目标项目
   AGENTS.md 索引块)明确豁免;且本仓 drift 实证(14 例仅 2 例涉压缩,§6.1)表明「token 多 →
   跑偏」本身是弱链。

## 2. 问题陈述(原始关切)

- **现象**:从 GLM5.2 起(今天 GLM5.3 依旧),模型写的中文技术文档对人类越来越难读。早期模型
  (GLM5.1 及更早,另一个项目)没有这个问题。
- **典型症状**(取自 `openspec/changes/harden-mgh-init-scout-path-binding/`,但**远不止此 change**,
  全仓产物普遍同病):
  - 「运行域」「锚」——无定义的生造/借用压缩词;
  - 「治类,非治个例」——文言式压缩;
  - 「插件进程 env 不继承 mid-session 导出」中的 `mid-session`——英文词裸嵌中文;
  - 「来源层 = producer 物化 repo 锚 + reader 统一拒识 recipe」——名词化代数式,无主语无动词。
- **波及面**:研发侧(spec 工件 / AGENTS.md / 契约 md)**和**用户侧(分发提示词、终端报告)。
  维护者说「每一个产物都有此现象,没有一个是无辜的」。
- **两个目标**:(a) 维护者能看懂每个迭代在干啥;(b) 目标项目用户能看懂工具在干啥。

## 3. 成因分析

### 3.1 模型层(「口音」——不可控,但可在产物上对冲)

| 机制 | 表现 | 例(均取自本仓工件) |
|---|---|---|
| 英文词当语义原子 | 怕翻译失真,干脆保留英文原词;非代码概念也如此 | `reader 统一拒识 recipe`、`shaping 失败用 recipe` |
| 名词化等式句 | 一句话压成「A = B 动词 C + D 动词 E」,删光主谓宾与因果 | `来源层 = producer 物化 repo 锚 + reader 统一拒识 recipe` |
| 生造压缩词 | 从别的领域借罕见译法或自造词,单字有出处、合起来没人认识 | `物化`(数据库 materialize)、`拒识`(生物识别)、`锚`、`接线不变量`、`治类非治个例` |
| 写给「共享全部上下文的自己」 | agent 写给下个 agent 读的场景变多;写给自己 = 不交代背景、不重复、不举例。而**人类阅读靠冗余活着**(同义复述是读者的锚点) | 每句悬在 `R5.5①`/`D3`/`G2`/`承 harden-…` 引用网上,抽掉一格整段崩塌 |

**诚实边界**:
- 「GLM5.1 时代没有」无法核实训练细节,且有一个**混杂变量**——项目本身也在变:早期移植 vvaharness,
  产出以代码 + 英文提示词为主;后期全是原创中文元工程文档(spec / AGENTS.md / 契约)。「模型口音变了」
  与「项目文体变了」两个变量一起动。
- 但这不影响对策:口音是**每类产物上可以约定的写作要求**,不需要等模型改。

### 3.2 项目层(放大器——全部可控)

1. **R3 明文「面向 AI 阅读」**——人类可读性从章程上不在验收范围。规则不仅在允许变难,它在**奖励**变难。
2. **R5.5 措辞纪律外溢**——RFC-2119 动词、`NEVER`、「禁令清楚则不举例」本是为 subagent 指令设计的
   功能性约束(让弱模型服从),但同一语域渗进了所有写作,包括给人看的部分。
3. **自消费架构**——本仓设计哲学是「磁盘是真相源、进度由 agent 从磁盘重推导」;spec 是 `opsx:propose`
   (agent)写给 `opsx:apply`(agent)的。整条链路没有任何一环的验收标准是「人能读懂」。
4. **术语通胀无词典**——每个 change 都在造新词(锚 / 物化 / 拒识 / 哨兵 / 运行域 / 承 / 兑现…),然后
   全仓传播。没有词典,浊度按复利增长。

## 4. 关键事实:解药已存在

`docs/r5-plain-language.md`(AGENTS.md R5 段的人类桥梁版)是**全仓唯一**能顺畅读完的长文档。它做对两件事:

- **四要素结构**:每条规则 = 说什么 / 为什么有这条 / 违反会怎样 / 什么兜底;
- **开头一张术语表**:反复出现的词先集中释义一次。

**推论**:模型被明确要求时完全写得出人话。问题不是能力,是**没有要求**。方向不是对抗模型默认口音,
而是**给每类产物声明受众;人读的那层强制人话**。

核心结构问题一句话:**一份产物,两类读者,需求相反。**

```
              人类(维护者 / 目标项目用户)              agent(下一会话 / subagent)
                    │                                    │
  需要: 现象→原因→改法;术语有定义;          需要: 精确、无歧义、省 token;
        允许冗余;例子越多越好                     指令短促(NEVER/MUST)
  时机: 偶尔读、冷启动、无上下文               时机: 每次读、带着全部上下文
                    │                                    │
                    ▼                                    ▼
            人话层(先写)──── 压缩 ────▶          术语层(后写,每个术语可回溯展开)
```

现状 = 只有压缩后的产物、没有源码对照表。修法**不是停止压缩**(压缩形态对 agent 是功能性的),
而是**把对照留住**:人话版先写(它是 explore/propose 讨论时本来就存在的人话快照,只是从未被持久化),
术语版后写。

## 5. 担忧 1 与答复:改提示词会不会让执行效果变差

**担忧**:当前版本提示词经过实测验证可靠;改描述让人易懂,会不会破坏可靠性?

### 5.1 可靠性资本的分布不均匀(答复的前提)

| 层 | 内容 | 可靠性资本 | 改动风险 |
|---|---|---|---|
| agent 操作指令层 | NEVER 链、verbatim 路径配方、flag 表、`--check` 闸门、fan-out 三元组、stage 纪律段 | **极高**(「保真度优先」纪律,AGENTS.md R5.6 / 旧报告「⚠ 裁剪前提」:看似冗余的 mantra 是针对真实失败形状的承重防御) | 高,且无必要 |
| 壳内解释性散文 | `--include-tests` 理由段、hook 机制 blockquote | 中(纯解释为主,但混着承重边界披露) | 中:逐条先验真 |
| 终端产物的生成指令 | 告诉 subagent「report.md 怎么写」的段落 | 低(改输出文体,不改管道行为) | 低 |
| 新增独立人话文件 | man 式说明、词典 | 无(agent 从不加载) | **零** |

「动提示词 = 拿验证过的东西冒险」只对第一层成立——方案恰好完全绕开第一层。

### 5.2 规避架构:受众按**文件**分离,不按段落

```
        ┌─ agent 载荷面(进上下文) ─────────────────┐   ┌─ 人类专属面(不进上下文) ──┐
        │  壳纪律段 / stage 提示词 / flag 表         │   │  docs/man/<cmd>.md        │
        │  JSON schema / NEVER 链                   │   │  docs/glossary.md         │
        │        —— 字节不动 ——                     │   │  proposal 人话序          │
        └───────────────────────────────────────────┘   └───────────────────────────┘
                            ▲ 唯一交点 ▲
                  壳内一行指针:「人类读者:通俗说明见 …」(~20 tok)
                  + 终端产物(report / 详述文件)的生成指令要求人话语域
```

- **用户侧看懂工具**:man 文档(分发到目标项目但**无任何提示词引用它**,agent 不加载)+ 终端产物
  本身人话化。壳内零必改项。
- **维护者侧看懂迭代**:proposal 人话序 + 词典 = 研发仓文件;`docs/` 本就在
  `tools/check_distributed_purity.py::SCAN_DIRS` 之外(见 `docs/r5-plain-language.md:5`),零分发。
- **立场纪律**:不主张依赖「人话版对弱模型执行更好」的未验证正面效应。方案的立场是:必做部分对
  执行的影响**恰好为零**(可证明:agent 不读这些文件),而非「可能还有好处」。

### 5.3 唯一动既有提示词的点 + 闸门

终端产物(report.md、`docs/security-controls/<cat>.md`)的文体由 stage 提示词决定,人话化**必须**
改对应 stage 的输出要求句(如 init-rulewriter 输出要求、render 侧指令)。处理方式:

1. **只改输出要求句,不碰行为指令**——写什么字段、过什么 lint 全部不动,只加「面向人类读者、术语
   首次出现给一句解释」的语域要求(~30 tok/stage);
2. **走 R5.7 段 A 闸门**——baseline ≥5 次、blind A/B 对比 pass rate + tokens(本仓为「改提示词怕变差」
   发明的流程,本次不豁免);
3. 结构产物(`controls_inventory.json`、checkpoint JSON)**完全排除**——机器消费面一字不动。

## 6. 担忧 2 与答复:token 增加会不会提前触发 150K 内的注意力稀释

**担忧**:不是怕贵,是怕用户侧模型上下文窗口 150K,token 消耗更多 → 更早注意力稀释 → 效果变差。

### 6.1 源码核实结论与证据链更正(权威 = mgh-init-budget-analysis.md)

**证据链更正(2026-08-17,承维护者指出)**:本节原以 `docs/review-prompt-length-budget-150k.md`
§2.1/§9.1 为据——该报告已被 `docs/mgh-init-budget-analysis.md` §0 明文**取代**(「后者已废」)。
旧报告的**实测数据表**(§3 各命令 token 基线)仍可引用,但其预算模型/收益归因有四点已立案错漏:

| # | 旧报告错漏 | 权威版纠正 |
|---|---|---|
| 1 | §9 把 fragment 收益归因为「非每轮 system 税」——为真但**与收益无关** | 真收益 = 内容迁入工具输出区(prune 可回收);且该收益**仅 opt-in 用户成立**(§0/§1.2) |
| 2 | 未察觉 `compaction.prune` **默认 false**(`config.ts:154-156`),行文暗示 Read/fragment 输出会「自然老化」 | **默认用户 prune 从不运行**:Read/Bash/subagent/fragment 单调累积到 ~130K 压缩,无早回收;且 prune 为 v1-only,v2 无(§1.2 纠错 2) |
| 3 | 把「缩壳」与「哨兵可靠性」捆绑论述 | 两个正交问题,治本路径各自独立(§2) |
| 4 | 总框架 = 省 token | 真实目标 = **准确度/防跑偏**;14 个归档 drift-fix spec 仅 2 个涉压缩(§A.1) |

**纠正后仍成立、本答复继续依赖的结论**(权威版 §1/§3,机制行号见 `docs/opencode-context-mechanics.md`):

- 命令壳 = **一次性 USER 历史项**,不随轮次累乘;但它是**驻留至压缩的常驻开销**(USER 文本区只有
  压缩一条回收路)——每短 1 tok 都真省,且壳处于 primacy 区;
- 150K 模型 **~130K 触发有损压缩**(阈值 ≈ `input − reserved`,`reserved = min(20000, maxOutput)`,
  `overflow.ts:8-34`);触发由**累积量**驱动(工具输出 + 目标 AGENTS 为主,壳是小的常驻贡献者)
  ——「壳大 → 更早压缩」弱因果维持撤回,「壳大 = 全程常驻预算」成立;
- 注意力稀释是 **lost-in-the-middle 位置问题**(关键信息埋中段才掉准),与总量关系弱;
- **prune 默认关**(错漏 #2)⇒ 默认用户侧一切 agent 读入(含 lazy Read 详述文件)都是「读入即
  驻留至压缩」,无自动回收红利——§6.2 的账按此保守口径计。

**实证补强**(权威版 §A.1,比机制论证更硬):14 个归档 drift-fix spec 仅 2 个与压缩相关(且均为
多层根因之一),12 个是契约/path/shape/纪律 gap——「token 多一点 → 更早跑偏」在本仓自己的实证里
就是弱链;真跑偏源恰是本方案承诺**字节不动**的那一层(§5.1 表第一行)。

### 6.2 人话化各载荷的 token 路径账

| 载荷 | 进上下文路径 | 频率 | 增量 | 对 130K / 注意力影响 |
|---|---|---|---|---|
| 壳内 20 tok 指针行 | 触发轮 USER 历史 | 每 run 1 次 | +20 | +0.015%,噪音级 |
| man 文档 / 词典 / proposal 人话序 | **无**(无提示词引用) | 0 | 0 | **零** |
| report.md 等终端产物 | 生成后**不回灌**管道 | 0(管道内) | 文件 +30–50% | 零(纯人读) |
| security-controls 详述文件 | 目标项目 lazy Read(**读入即驻留至压缩**——prune 默认关,无早回收) | 按需低频 | 见 6.3 长度账 | 小(每次读入 = 全文件字节,故 6.3 的 1.3× 软上限必要) |
| **AGENTS.md 索引块** | **目标项目每轮 system 重读**(SYSTEM 块每轮重派生、含目标 AGENTS;权威版 §3.1) | **每轮** | — | **唯一的雷:豁免,保持现状精简形态** |

### 6.3 「人话 = 更长」是误解,拆两笔账

- **白难移除**(英文原子→中文、等式句还原主谓、生造词换常用词):**~1–1.5×**,很多地方反而变短
  (§8 实例:那句「来源层 = …」的最小人话版只多 ~15 tok);
- **解释成本**(术语定义、为什么、举例):**2–3×**——这笔钱**不内联**,花到词典和 man 层(不进上下文)。

预算纪律一句话:**内联只做白难移除,解释全部外置**。详述文件加软上限(≤ 现长度 1.3×)进 lint。

### 6.4 与在途超限项的关系(避免混淆)

sra-augment a3(5,274/6,288)、sast-deepdive s4(6,989)、sra/srr 壳(5,460/5,148)的既有超限是旧预算报告
§7 已立案的任务 2–5(数据基线仍有效;该报告模型/归因错漏见 §6.1 表),与人话化无关。本方案**不新增任何走「子 agent 有效系统 ≤5K」受限路径的 token**
(stage 行为段一字不动;输出语域要求 ~30 tok 且 init-rulewriter 最坏路径 4,040 尚有余量)。

## 7. 方案边界(v2,已按两大担忧修订)

| 部分 | 内容 | 动既有提示词? | agent 上下文成本 | 需 A/B? |
|---|---|---|---|---|
| **必做 A** | R3 修订(受众声明制:每份产物声明给谁读;人类面走人话规范;R5.5 措辞纪律只管辖 agent 指令)+ proposal 模板加人话序(现象→根因→改什么→怎么验证,~200–300 字,先写后压缩)+ `docs/glossary.md` 种子(从 AGENTS.md 与 r5-plain-language.md 术语表起步 ~30–50 条;规则:产物用词前词典必须有)+ CI 代理 lint | ❌ | 0 | ❌ |
| **必做 B** | `docs/man/<cmd>.md` ×5(mgh-sast/init/sra/srr/ut-init 人话版说明:这命令做什么 / 会动我项目哪些文件 / 产出什么 / 风险边界)+ 每壳一行人类读者指针 | ❌(纯新增) | +20 tok/命令 | ❌ |
| **必做 C** | 终端产物语域要求:report.md、详述文件面向人类;**排除** AGENTS.md 索引块、一切 JSON / 中间 checkpoint | ✅ 仅输出要求句(~30 tok/stage,§5.3) | 输出侧 | ✅ R5.7 A/B |
| **不做** | 改写壳内操作散文、NEVER 链、stage 行为段、批量「顺手美化」 | — | — | — |

**人工闸门(零成本,进流程)**:change 的就绪标准加一条——维护者只读人话序 + tasks.md,能复述出
这个 change 在干嘛;做不到 = 没就绪。把「读不懂」从事后抱怨变成流程内正确时机的否决票。

**时序**(与在途 change 的关系):
- 在途:`harden-mgh-init-scout-path-binding`(0/20)、`add-mgh-ut`(0/20)、`extract-ut-shared-helpers`(0/14)。
- A 的 R3 修订与 scout-path-binding 的 AGENTS.md R5.7 段改动**同文件不同段**,轻度交集,建议错开合入;
- B 的 5 壳指针行:经核对,壳本体不在在途 change 的 Impact 清单,冲突低;可独立小 change 或随下一个
  触碰该壳的 change 顺带;
- **C 必须等** add-mgh-ut 与 scout-path-binding 落地后再做(同文件双 change 冲突;承 memory 教训
  「拆分跨切 change 保持 apply 上下文有界」)。

## 8. 翻译示例(证明可行且不太费字)
