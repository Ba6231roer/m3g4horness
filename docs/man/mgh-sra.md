# /mgh-sra 使用说明(人话版)

> 受众:人类。本文件是说给你听的通俗说明;命令的完整技术定义在命令壳 `.md` 里,给 AI 读。

## 这命令做什么

在你用 openspec 提出一个变更(proposal 阶段、还没合入)之后跑它:AI 从九个安全维度
(认证、授权、加密、审计日志……)逐条检查这个变更的设计和任务清单,**找出安全上没考虑到
的缺口**,然后把补缺的需求和任务直接写回变更文档里。

它不只是报问题,还会先看你的项目里**已经有哪些安全措施可以复用**(如果你跑过 `/mgh-init`,
就直接用那份清单),给出的建议会尽量贴合你项目的现成做法,而不是给一堆泛泛的「最佳实践」。

过程中它会**批量向你提问**(比如「这个接口哪些角色能调?」),你的回答会沉淀成一份项目级的
「业务记忆」,存在你的项目里;下次再跑 `/mgh-sra`,它记得这些事实,不重复问。

## 会动你项目里的哪些文件

- **新建** `<变更目录>/.mgh-sra/`:分析过程的中间产物(结构化上下文、澄清问答、增补草稿)。
- **修改变更本身的文档**:往 `specs/<能力>/spec.md` 和 `tasks.md` 里追加安全需求和任务。
  追加的内容放在标记块内,重跑只更新标记块内部,块外内容不动。
- **新建/更新** `<你的项目>/.mgh-sra/business_context.json`:跨变更累积的业务记忆。
- **不会**改你的源代码。

## 产出什么

| 文件 | 是什么 |
|---|---|
| 变更 `specs/` + `tasks.md` 里的增补 | 补上的安全需求与任务(标明出处指向变更里的具体条目) |
| `.mgh-sra/change_context.json` | 机器可读的变更上下文,供后续工具复用 |
| `.mgh-sra/clarifications.json` | 它问你的问题清单 |
| `.mgh-sra/sra_manifest.json` | 本次运行的统计和边界记录 |
| `<项目>/.mgh-sra/business_context.json` | 项目级业务记忆(角色、接口权限、敏感字段) |

## 风险与边界(诚实披露)

- **增补内容是「AI 给的候选」,需要人复核**后再采纳,不是权威结论。
- 它只能看到变更文档里**写了的**东西和你**回答过**的业务事实;没写、没答的它不知道。
- 引用已有安全措施时,它断言「这个项目里有这个措施」,不断言「这个措施真的有效」——
  有效性要你自己验证。
- 涉及个人敏感信息(姓名、身份证号、手机号这类)的项目,可以给它一份敏感字段目录
  (安装时会放一个模板在你的 `.mgh-sra/` 下),分析会更准;不给也能跑,只是粒度粗。
