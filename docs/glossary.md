# 术语词典(glossary)

> **受众:人类**(R3 受众声明制)。本词典是所有人类面产物(`docs/man/**`、proposal 人话序、
> 终端报告)的用词后盾:**人类面产物用到的术语,这里必须有条目;缺则先补这里,再写进产物**。
> 词典自由增补,不设准入审批。
>
> 英文术语保留英文原文(它们是本仓的操作性词汇,翻译反而歧义),但每条都给中文大白话释义。

| 术语 | 大白话释义 |
|---|---|
| agent / subagent | agent = 跑这些命令的 AI(Claude Code / opencode)。subagent(子 agent)= 由主 agent 派生、拥有独立上下文窗口的子任务执行者,干完活把结论交回,不共享主 agent 的对话历史。 |
| 编排器(orchestrator) | 把多阶段流水线串起来的角色。本仓的编排器**就是宿主 agent 自己**——按命令 `.md` 里的步骤用自身工具逐步跑,不是一段代码。 |
| 命令壳(shell) | `/mgh-*` 命令的 `.md` 定义文件。装进目标项目后,宿主 agent 输入 `/mgh-init` 之类的命令时把它当提示词加载执行。 |
| hook(钩子) | 宿主在工具调用前后插入的自定义拦截逻辑。本仓用它运行时拦下 agent 的越权操作(乱写脚本、写出目标目录之外)。claude 侧叫 `PreToolUse` 命令,opencode 侧叫 `tool.execute.before` 插件。 |
| 守卫(guard) | `block_adhoc_scripts.py`,hook 背后那段判定逻辑。检查每次写文件/读文件/跑命令的请求,越界的直接拒绝。 |
| 运行域(runtime domain) | 某个 `/mgh-*` 命令正在运行的期间。用环境变量(如 `MGH_INIT_ACTIVE=1`)或磁盘上的标记文件声明;hook 只在运行域内拦截,平时不干扰你正常写代码。 |
| 哨兵文件(sentinel) | 磁盘上的 `.active` 小文件,内容是「现在有个 mgh 命令在跑、目标是哪个目录」。命令开始时写、正常结束删除。解决「opencode 的插件进程读不到会话中途导出的环境变量」问题——文件在磁盘上,谁都能读。 |
| stdout / stderr | 进程的两条输出流。stdout(标准输出)走结构化数据(本仓是 JSON);stderr(标准错误)走日志和进度。两边严格分开,否则下游解析 JSON 会炸。 |
| 退出码(exit code) | 进程结束时的数字信号:0 = 成功;1 = 通用错误;2 = 用法/契约错误(参数错了、产物校验没过)。fail-loud = 出错立即非 0 退出并停下;fail-soft = 出错只警告、流程继续。 |
| flag | 命令行参数,如 `--repo`、`--check`。脚本的 `--help` 输出就是它支持的全部 flag 清单,agent 靠读这个学接口(不读源码)。 |
| `--check` | 每个产出中间产物的脚本都带的自校验开关。编排器跑完一步就执行一次,失败(退出码 2)就回退重跑那一步,不带病前进。 |
| 零运行时依赖(zero runtime deps) | 不需要 `pip install` 任何第三方包,只用 Python 标准库。内网无网环境也能跑,这是产品特性,不是临时状态。 |
| AST 扫描 | 把 Python 源码解析成语法树后静态检查。本仓用它机械验证「零依赖」(扫所有 import 语句),不用真的去跑安装。 |
| 幂等(idempotent) | 同一操作重复执行结果不变。install 跑两遍不会坏,脚本重跑会跳过已完成的单元。 |
| fan-out(扇出) | 一项大任务拆成多个并行子单元,每个 subagent 跑一个。比如把 100 个文件分成 10 批,派 10 个 subagent 各查一批。 |
| checkpoint(检查点) | 长任务里每个子单元干完活留下的完成记录文件(`.done` 标记 + 产物 JSON)。重跑时看到检查点就跳过,实现「断点续跑」。 |
| `--resume` | 断点续跑开关。配上 checkpoint 机制,大任务被中断后(超时、上下文压缩、会话崩溃)从断的地方继续,不从头再来。 |
| recipe / prohibition | 两种写规则的姿势:recipe = 正引导(「要 X 就去做 Y」);prohibition = 禁令(「别做 X」)。本仓规则优先用 recipe,只有硬边界才用禁令。 |
| 硬边界(bright-line) | 清晰、无模糊空间的绝对禁令,如「零依赖」「跨格式产物不混」。区别于可协商的偏好。 |
| RFC-2119 动词 | `MUST`/`SHALL`/`SHOULD`/`MAY` 这组规范动词,机器可检测。规则文本用它们取代口语化的「应该/可以」。 |
| front matter | md 文件头部的 `---` 元数据块。opencode 的命令定义靠它声明 `description` 等字段。 |
| cwd(当前工作目录) | 进程运行时所在的目录。脚本必须对任意 cwd 安全——无论从哪个目录被启动,都能正确定位自己和输出路径。 |
| SAST | 静态应用安全测试:不运行代码,直接分析源码找安全漏洞。`/mgh-sast` 干的事。 |
| 调用图 / callgraph | 「哪个函数调用了哪个函数」的关系图。用于判断一个改动会波及哪些代码。本仓的实现是文本/AST 级,看不懂反射和框架路由,漏掉的会写进 `unresolved[]` 披露。 |
| 安全控制(security control) | 代码里已经存在的防御措施,如输入校验、权限检查、输出编码。`/mgh-init` 的任务就是把它们全部找出来。 |
| controls_inventory.json | `/mgh-init` 的核心产物:一份机器可读的「本项目已有哪些安全控制」清单,每条带证据(文件、行号、代码片段)。 |
| 规则(rules) | `/mgh-init` 产出的、给目标项目 agent 看的安全规则文件。claude 侧放 `.claude/rules/`(按路径自动生效),opencode 侧写进 `AGENTS.md` 索引块 + 详述文件(按需加载)。 |
| T1 / scout / T3 | `/mgh-init` 内部的分层阶段标签:scout = 分批探查源码;T1 = 按簇归纳每批发现;T3 = 按类别汇总成最终规则。tier(层)= 这些阶段的统称。 |
| s1..s9 | `/mgh-sast` 九个阶段的编号:s1 调查 → s2 威胁建模 → s3 分解 → s4 深挖 → s5 预过滤 → s6 验证 → s7 去重 → s8 链接 → s9 出报告。 |
| 维度(dimension) | `/mgh-sra` 做缺口分析时依据的安全维度(认证、授权、加密、审计等),每个维度逐一检查有没有对应的设计。 |
| 业务记忆(business context) | `/mgh-sra`/`/mgh-srr` 沉淀的项目级事实文件(`business_context.json`):有哪些角色、哪些接口谁有权调、哪些字段敏感。跨迭代复用,越用越准。 |
| 受管块(managed block) | 工具写进你文件里的一段带开始/结束标记的内容。重复运行时只替换标记之间的部分,标记外的内容一字不动。 |
| SARIF | 静态分析结果的行业标准交换格式(JSON)。`/mgh-sast` 最终报告用它,可导入各种告警平台。 |
| CVSS | 漏洞通用评分体系(0–10 分)。`/mgh-sast` 给每个发现算严重度分。 |
| CWE | 常见弱点枚举编号,如 CWE-89(SQL 注入)。给每个发现归类用。 |
| 端口-适配器(ports & adapters) | 一种架构模式:核心引擎不动,两头做格式转换。`/mgh-srr` 靠它复用 `/mgh-sra` 的全部中间逻辑,只换了输入(自由文本)和输出(普通报告)两个「适配器」。 |
| 人话序(plain-language preamble) | 每份 proposal 开头那段大白话:现象→根因→改什么→怎么验证。给维护者看,也给执行 agent 提供背景。 |
| 受众声明制 | 每份产物声明给谁读(人类/agent/双受众),按 R3 的受众分类表归类。人类面说人话,agent 面保持机器可检的紧凑措辞,互不越界。 |
| 人工闸门(human gate) | 一道流程检查:维护者只读 proposal 人话序 + 任务清单,能复述这个 change 在干嘛。做不到 = 未就绪。这是机器测不了「真可读性」的唯一兜底。 |
| agent 面 / 人类面 | agent 面 = 给 AI 读的操作文件(命令壳、stage 提示词、契约);人类面 = 给人读的说明(man 文档、词典、人话序)。两类文件措辞规范不同,见 R3 受众分类表。 |
| 越树(out-of-tree) | 写/读操作的目标路径不在被分析项目的目录树之内。运行域内这是违例(会把产物写到错误的地方,历史上真发生过「输出漂到 D 盘根」),hook 直接拦。 |
| 白名单豁免(allowlist) | lint 工具的行级例外机制:已知误报的行列进一个文本文件,lint 跳过它们。用于消化不可避免的假阳性。 |
| headless(无头模式) | 不开交互界面、一条命令直接跑完拿结果的调用方式,如 `opencode run "..."` / `claude -p "..."`。fan-out 派发器 spawn 的就是这种子进程。 |
| 回执(ack) | 子任务跑完后回传的**单行**约定格式消息(`ok <路径> <数量>` / `failed <原因>`)。派发器只解析这一行,不读产物内容,防止子任务输出把编排器上下文撑爆。 |
| wave(波次) | fan-out 的一批并发:一次同时派 N 个(默认 5)子进程,全收完再派下一批。并发的粒度单位。 |
| 软时限(soft deadline) | 脚本自己设的「到点就不再发新波、等在飞的跑完、干净退出」的时间预算(`--time-budget-ms`)。必须早于宿主的硬超时触发,否则会被硬杀丢掉在飞的一波。 |
| sidecar(伴生文件) | 主产物之外、给人看的辅助状态文件(如 `fanout_progress.json`):脚本边跑边更新,人开第二个终端盯着看;agent 不读它,坏了也不影响主流程。 |
| 锚树校验(anchor-tree check) | 把路径 resolve 成绝对路径后检查它是否落在目标项目目录树之内,越界(如漂到盘符根)即拒绝。fan-out 派发器在 spawn 前做,守卫 hook 在运行时做。 |
| centralized / distributed | `/mgh-init` 簇(`clusters.json::clusters[]`)的两种**归簇形态**。centralized = 控制定义在一处(一个 util / filter / config / interceptor 类),按**锚点** `category::anchor::file` 归簇,典型例子:`SecurityConfig` 里整套授权配置;distributed = 注解类控制跨文件散落,按 **token** `category::pattern` 归簇,典型例子:`@PreAuthorize` / `@Valid` 出现在很多文件里。`shape` 字段取值二者之一。 |
| cluster_id | `/mgh-init` 每个簇(`clusters.json`)的**确定性单元标识**。组成形态:`{category}::{anchor}::{file}::{sha8}`(centralized 簇)或 `{category}::{pattern}::{sha8}`(distributed 簇),`sha8` = 完整 key 的 sha1 前 8 位 hex。用途:T1 的隔离/续跑单元名、检查点记录与扇出路径的基准。总长 ≤ 160 字符(超预算截显示槽位、保留 sha8 判别尾);含 `::`(NTFS 分隔符),落盘文件名须消毒。 |
| wrapper 字典 | 顶层是一个 dict、真正的列表数据挂在某个键下的 JSON 形态(如 `{"repo": "...", "clusters": [...], "truncated": false}`)。对**顶层** `len()` 得到的是键的个数(上例 = 3),**不是**数据条数——数列表要读对应键(`clusters[]`)或读产出者 stdout 的计数字段。 |
| 安全设计符合性复核(SDR) | `/mgh-sdr` 干的事:不是扫描找漏洞,而是对照项目里**已经定好的安全规矩**,检查这次代码改动有没有漏按规矩做。 |
| 存量安全设计 | 项目里已经定下来、并写进规则文件的安全做法(哪些接口要鉴权、SQL 必须参数化、敏感字段要脱敏……)。由 `/mgh-init` 产出,`/mgh-sdr` 拿它当检查基准。 |
| diff / base..branch | git 对两个分支做比较、列出所有改动。`base..branch` 表示「从 base 分支到当前分支改了什么」。`/mgh-sdr` 的输入就是这份 diff。 |
| 检查基线摘要(baseline) | 开工时从存量安全设计里按字节预算投影出的一份「这次评审要对照哪些规矩」的摘要;太长就按优先级截断(接口授权 > SQL > 输入校验 > 敏感数据)。 |
| 外部仓(外部前端仓) | 与后端主仓分开存放的前端项目目录。存量安全设计可能引用它(如「这个按钮在配置文件里配了权限就算合规」)。 |
| 受控检索 | 在编排器主流程内(不是子代理)对外部仓做有限的、预算内的检索,把结论物化成本仓内小文件;子代理永不直读外部仓,所以不会半路弹权限打断。 |
| slice 文件(只读切片) | 从 diff 里切出的一小份只读文件,含某个评审单元的改动 hunk 和邻近上下文。子代理只读这个,不读全量 diff。 |
| 变更符号 | diff 里改动的代码所归属的那个方法/接口。分组以它为节点。 |
| 接口调用链 | 一次接口请求从 controller 到 service 到 dao 的完整调用路径。分组要把落在同一条链上的改动并成一个单元。 |
| 越权(垂直/横向) | 垂直越权 = 低权限用户调到高权限接口;横向越权 = 用户 A 拿到用户 B 的数据。`/mgh-sdr` 的默认检查维度之一。 |
| 三元组去重 | 汇总时按「维度 + 接口 + 问题描述」三要素判断两条发现是否重复,重复的合并。避免共享下游被审多次产生报告噪声。 |
| codegraph | 外部图谱工具(可选):预计算符号、调用边、框架路由。项目建了 `.codegraph/` 索引且机器有命令才启用。 |
| launcher(启动脚本) | `mgh_sdr_launch.py`,人/定时任务用的一条命令入口:负责立哨兵、做外部仓受控检索、拉起宿主会话跑 `/mgh-sdr`。 |
| 敏感目录(sensitive catalog) | 一份「本项目哪些字段算敏感(手机号/身份证/卡号…)、该怎么屏蔽」的清单文件。`/mgh-sdr` 用它判断「敏感信息没脱敏」。 |
| 台账(manifest) | 机器可读的汇总文件(如 `sdr_manifest.json`),记各类计数和边界披露,供 `--check` 校验与断点续跑锚定。 |
