## Purpose

为「编排器直派原生子代理」的运行树提供进程外安全网:独立于编排会话存活,通过本机宿主服务的
HTTP 面观测根会话及其后代的活跃、等待与进展状态,对等待授权/问询代答拒绝、对超时无进展的
后代中止,动作全部留痕且支持先审后动;作用域外零触碰、零标记写入、零服务重启。

## ADDED Requirements

### Requirement: 服务发现限定于本机回环与凭据轮换容忍

`native_watchdog.py` SHALL 以确定性叶脚本形态实现(零依赖、任意 cwd、`--help` 即契约)。
服务发现 SHALL 依序:`--service-json <path>` 显式值 > `[XDG_STATE_HOME 或 ~/.local/state]/
opencode/service.json` 缺省路径;注册文件含 `{url, password, …}`,鉴权用 HTTP Basic(固定用
户名)。**回环限定**:解析出的 url 主机 SHALL ∈ {127.0.0.1, localhost, ::1},否则退出码 2
(NEVER 连接非本机服务——看门狗携带可动写凭证的本机密码,绝不应指向远端)。鉴权失败或连
接丢失时 SHALL 重读注册文件再试(宿主服务重启后会换密码;重读后仍失败计入不可达)。

#### Scenario: 缺省发现并连接本机服务

- **WHEN** 无 `--service-json`,本机存在缺省路径的 `service.json`(url 为回环地址)
- **THEN** 看门狗以注册文件凭据连接成功,首个巡检周期完成——发现即用,无需额外配置

#### Scenario: 非回环 url 被拒绝

- **WHEN** 注册文件(或覆盖值)的 url 主机不是回环地址(如局域网 IP 或域名)
- **THEN** 退出码 2 + 一句 recipe(说明仅限本机服务)——不发起任何连接

#### Scenario: 服务重启换密码后自动重读

- **WHEN** 巡检中鉴权失败或连接丢失,且注册文件已随服务重启更新
- **THEN** 重读注册文件并恢复巡检;重读后仍失败按不可达计数,达到阈值反映在退出状态里

### Requirement: 运行树所有权圈定与树外零触碰

看门狗的作用域 SHALL 是「根会话 + 其全部后代」:根会话 id 取 `--root` 显式值 >
`OPENCODE_SESSION_ID` 环境变量(宿主 shell 工具自动注入);后代按父 id 递归枚举收集。**每
次动作前 SHALL 重新校验目标会话的祖先链仍收敛到根**(会话树在运行中变化);校验不过则放
弃该动作并记录。树外会话 SHALL 只被「列表枚举」这一只读操作涉及,NEVER 成为任何处置动作
的目标。根会话 id 在服务上不存在时 SHALL 退出码 2 + recipe(而非空转)。

#### Scenario: 树外会话绝不被处置

- **WHEN** 共享服务上存在本 run 树之外的会话(用户自己的其它工作),且其中有等待授权项
- **THEN** 看门狗不对其执行任何动作(不在树内),其等待项原样保留——共享服务上他人的工
  作零干扰

#### Scenario: 动作前祖先链复核

- **WHEN** 某后代会话在枚举后被移出树(父链变化),看门狗仍持有其旧快照
- **THEN** 处置动作前的祖先链复核失败,动作被放弃并记录「树外放弃」——NEVER 按过期快照
  行动

#### Scenario: 根缺失 fail-loud

- **WHEN** `--root`(或环境变量)给出的会话 id 在服务上不存在
- **THEN** 退出码 2 + recipe(检查 root 传参/服务是否重启)——不进入空巡检

### Requirement: 巡检观测与卡住判定阈值

巡检以 `--poll-s` 周期(缺省 15 秒)对树内每个会话采集:活跃态、等待中的授权请求、等待中
的表单/问询、最近持久进展时间(会话更新时间、最新消息创建/完成时间、最新工具执行时间的
最大值)。授权与表单请求自身无时间戳,SHALL 由看门狗维护「首次见到」时刻并以宽限判定。卡
住判定阈值(全部可配,缺省值如下,语义为「收敛上界」而非健康诊断):

| 形态 | 判定 | 缺省 |
| --- | --- | --- |
| 等待授权 | 首见后超宽限 | 90 秒 |
| 等待表单/问询 | 首见后超宽限 | 90 秒 |
| 后代静默 | 活跃中且最近持久进展距今超窗 | 1200 秒(不低于宿主流超时+重试余量) |
| 后代超总时长 | 会话创建起超上限 | 3600 秒 |
| 中止未落定 | 中止后仍活跃超复核窗 | 45 秒 |

根会话 SHALL 适用授权/表单宽限(无人值守纪律对根同样成立),但**默认不适用**静默/超时中
止(见动作阶梯)。

#### Scenario: 宽限从首见起算

- **WHEN** 某等待授权项在连续多个巡检周期中存在(首见时刻 T)
- **THEN** 判定发生在 T+宽限 之后的首个周期——不是首见即动,也不是无宽限立即拒绝(给在
  场的人留反应窗,兼顾纯无人值守场景由阈值配置收窄)

#### Scenario: 静默窗与宿主超时余量

- **WHEN** 后代会话活跃但最近持久进展距今未超过静默窗
- **THEN** 不判卡住(宿主自身的响应头/流超时与重试尚在合理窗口内)——看门狗只设收敛上
  界,不抢宿主自愈的活

### Requirement: 动作阶梯与先审后动

处置动作 SHALL 按阶梯执行且全部受 `--dry-run` 约束(开启时只报告将执行的动作,零写请求):

1. **等待授权超宽限** → 回复「拒绝 + 一句替代做法提示」;SHALL NEVER 回复批准(once/
   always)——看门狗不是授权代理;
2. **等待表单/问询超宽限** → 取消并附提示(模型收到失败后继续本回合);
3. **后代静默或超总时长** → 中止该会话(其中止语义连带收口其挂起工具与 shell——宿主作
   用域机制负责,看门狗不直接管理 shell API);
4. **中止后未落定** → 复核窗后再中止一次;仍活跃则记录「未收口」(反映进退出状态),不
   无限重试;
5. **根会话静默/超时** → 默认仅记录;`--interrupt-root` 显式开启才可中止根(中止根连带取
   消整波在飞前台子代理,是最后手段)。

看门狗 SHALL 永不写任何单元完成/失败标记(标记唯一写者是单元执行纪律;被中止单元因无标
记自然回待办重派);SHALL 永不自动重启宿主服务(共享服务,重启是人的决定;不可达/未收口
只记录与反映)。

#### Scenario: 等待授权被代答拒绝后会话继续

- **WHEN** 树内某会话的等待授权项超宽限
- **THEN** 回复拒绝+提示,该会话的工具调用以失败返回、模型继续本回合——挂死解除,且绝无
  「批准」形态的回复

#### Scenario: 无进展后代被中止回待办

- **WHEN** 后代会话活跃但超静默窗(或超总时长)无持久进展
- **THEN** 中止该会话;其单元因无完成标记在下次待办重枚举中回到待派——「卡死占槽」变
  「有界失败 + 重派」

#### Scenario: dry-run 只报告不动手

- **WHEN** 以 `--dry-run` 运行且巡检发现超宽限授权与超静默后代各一
- **THEN** 事件流/摘要记录「将拒绝」「将中止」两类拟动作,服务端零写请求——破坏性动作
  可先审后动(对齐仓库既有纪律)

#### Scenario: 看门狗零标记写入

- **WHEN** 巡检期间发生任何处置
- **THEN** 磁盘上不出现任何 `.done`/`.failed`(或任何单元标记)的新增/删除——标记真相源
  不被看门狗污染,重派/收敛语义保持单一归属

### Requirement: 留痕工件与退出契约

传 `--run-dir` 时,看门狗 SHALL 把每条动作与关键观测追加到 `<run>/watchdog/events.jsonl`
(每行一个 JSON),并把运行树快照与判定状态原子写 `<run>/watchdog/state.json`(每巡检周
期至多一次;缺 `--run-dir` 时不落盘仅出摘要)。stdout SHALL 恰好一行 JSON 摘要(模式/周
期数/树内会话数/各类动作计数/未收口数/dry-run 标记/退出原因),stderr 走心跳行;严格分
流。退出码:0 = 树已落定(根与全部后代空闲且无等待项)或 `--deadline-s` 预算耗尽且无未
收口;2 = 存在未收口挂死、服务持续不可达或根缺失(需要人);1 = 误用。常驻模式 SHALL 自
退(落定或预算到点),NEVER 变成孤儿常驻;`--once` SHALL 单扫后立即退出(波次边界对账/
测试形态)。

#### Scenario: 落定自退

- **WHEN** 运行树的全部会话空闲且无等待项,持续一个确认周期
- **THEN** 看门狗写终态摘要后退出码 0——run 结束看门狗不滞留

#### Scenario: 未收口反映为退出码 2

- **WHEN** 某后代经两次中止仍活跃(未收口)且达到退出条件(预算/落定判定)
- **THEN** 退出码 2,摘要与 events 中含未收口会话清单——「需要人」的状态不被干净退出码
  掩盖

#### Scenario: 摘要与心跳严格分流

- **WHEN** 常驻运行若干周期后退出
- **THEN** stdout 恰好一行可解析 JSON(机器面),进度/诊断全部在 stderr(人面)——下游
  脚本可无歧义消费摘要
