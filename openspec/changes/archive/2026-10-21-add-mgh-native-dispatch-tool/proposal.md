> **人话序** 现象:超大仓库的批量探查(比如上千个待查单元)即使改成了原生子代理派发,编排器
> (一个较弱的模型)仍要「派一波、等结果、查进度、再派一波」地亲手循环几百轮——每轮都是一
> 次 LLM 回合,烧 token、慢、还可能在几十轮后走样,长跑会触发多次上下文压缩。根因:此前的原
> 生接入把「波次循环」留在编排器的模型回合里,这在几十个单元的复核场景够用,在几百上千单元
> 的场景退化为几百次回合;而宿主插件其实具备「在进程内直接创建并驱动子会话」的编程面,只是
> 没人用它。改什么:给宿主装一个自定义派发工具——编排器调用一次、传入计划文件引用与波次,
> 插件在进程内读计划、按波次并发创建子会话、等收完、再下一波,直到计划跑完;子会话的全部
> 语义(权限断言/嵌套深度/取消级联)与宿主自带的子代理工具对齐;任务全文由插件从计划展开,
> 模型输出里不再出现任何长路径。顺带把「编排器逐字转述任务文件路径」的最后残余错抄面也关
> 掉:同一插件提供令牌展开钩子,任务引用只写短号,钩子在执行前展开成全文。怎么验证:源码形
> 状锚 + 实机小规模全链(一次调用跑完多波、中断级联、幂等重入、未知短号报错);企业版宿主
> 做一次只读探测。

## Why

- 原生派发路线已落地四件基础件与 sdr 接入(五个 change 已归档),但 sdr 的通道 A(编排器
  每波亲手发子代理调用)在**数百至上千单元**的 init 场景会退化为数百次编排器回合 + 3–4 次
  上下文压缩——那是子进程派发器当年立项要消灭的形态,不能在原生路线里复活。
- 宿主 2.x 插件 API 已实测具备进程内会话编程面:插件可注册自定义工具、可编程式
  创建/驱动/等待/中止子会话、可做权限断言;「一次工具调用在插件内跑完全部波次」= 子进程
  派发器的进程内等价物:零 LLM 波次回合、认证同服务继承、守卫钩子照过。
- sdr 接入的 design 已把「插件令牌展开(任务引用只写短号,插件按计划展开任务全文)」列为
  路径转述残余(P4)的清零手段,候选并入本 change——工具的「短号进、全文出」形态与展开钩
  子同源同件,一并落地。
- 磁盘标记仍是唯一真相源:计划物化、标记判定、收敛纪律全部已在盘上,插件只做「读计划 →
  建会话 → 等收割 → 读标记 → 报摘要」的胶水,不引入第二判定源。

## What Changes

- **新增独立插件** `releases/opencode/plugins/mgh_dispatch.ts`(与守卫插件分文件,后者零触
  摸),注册自定义工具 **`mgh_dispatch`**:
  - **输入契约**:计划文件引用(接受绝对或项目相对形,项目根取插件位置;这是输入中唯一
    的路径形态字段)+ 可选 `wave`(单波模式;缺省 = 按计划顺序跑全部波次)+ 可选 `units`
    (短号数组,只派指定单元);**永不接收**任何单元的任务文件路径或产物路径;未知/不在计
    划内/已终态短号 → 工具错误 + 一句 recipe(不 spawn 任何会话)。
  - **派发语义与宿主内置子代理工具对齐**(缺一即安全/完成性缺口):每次创建子会话前做
    `subagent` 动作权限断言;沿父链走深度并按嵌套深度上限拒绝;拒绝 primary 模式 agent
    (计划携带 agent 名,须为 subagent 形态孪生);`description` = 单元短号;任务消息 = 该单
    元任务文件内容**逐字**(插件读文件,模型零撰写);波内并发 = 计划波次尺寸,波间顺序执
    行。
  - **收割与幂等**:每单元以磁盘标记分类(完成/失败/无标记),会话终态与标记不一致如实
    报「无标记」;**工具内不做重派**——重试机制 = 幂等重调用(标记感知跳过终态单元);
    返回紧凑结构化摘要(计数 + 失败/无标记短号清单 + 每单元会话 id),NEVER 携带 findings
    内容(详情在盘上)。
  - **标记真相源不变量**:插件 NEVER 写任何单元标记;NEVER 解读 findings。
  - **取消级联**:工具调用被中止时,中断其创建且仍活跃的全部子会话后再返回。
  - **配额自限**:项目根存在环境画像配额时,波间按「窗口内已派单元 × 每单元估算 + 估算 ≤
    窗口上限」的同一算术自限(估算口径与既有派发器一致),窗口余量不足则等到窗口滚动再派
    下一波。
- **令牌展开钩子**(同插件文件):`execute.before` 对内置子代理工具调用的任务文本做令牌展
  开——任务引用形如「计划引用 + 短号」的令牌行,钩子按计划展开为完整任务文本(模型输出从
  此不含长任务路径);未知短号/计划不可读 → 工具错误 + recipe;sdr 原生波次纪律 fragment 的
  中继行切换为令牌形(该钩子即刻有消费者,P4 残余闭环)。
- **分发面**:安装器从「只管一个插件文件名」扩为「固定文件集」(守卫插件 + 派发插件,仍
  NEVER 触碰用户其它插件);install 自检清单同步;CI 源码形状锚覆盖工具注册/取消级联/短号
  校验/令牌展开分支。
- **契约**:`core/contracts/fanout/runtime.md` native 段增「dispatch tool」子节(输入契约/
  语义对齐表/幂等/取消/自限/版本矩阵)。
- **非目标**:不改 emit_native_plan/native_watchdog/env_profile(计划产物只读;若需字段扩展
  走「可选字段、旧计划仍过 --check」);sdr 不切换到本工具(维持通道 A + 令牌展开);不做
  init 接入(第 7/8 个 change);不动 claude/dsh 面;不做工具内重派与限流判定。
