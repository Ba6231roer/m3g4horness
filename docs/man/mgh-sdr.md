# /mgh-sdr 使用说明(人话版)

> 受众:人类。本文件是通俗说明;命令的完整技术定义在命令壳 `.md` 里,给 AI 读。

## 这命令做什么

你的需求分支开发完了,准备合进版本分支(merge)之前,想让 AI 检查一遍:**这次改的代码,
有没有漏掉项目里已经定好的安全规矩**——比如「接口必须配权限」「查询必须校验机构」「SQL
必须参数化」「敏感字段必须脱敏」。`/mgh-sdr` 就是干这个的「合码前安全关卡」。

它不是漏洞扫描器(`/mgh-sast` 管那个),而是拿你项目里**已经写进规则的安全设计**(通常是
`/mgh-init` 产出的)当基准,把 `git diff base..branch` 的改动逐个接口对照检查。

## 会动你项目里的哪些文件

- **新建**:`.mgh-sdr/runs/<时间戳>/`(评审过程产物:slice 切片、草稿、外部仓结论、台账)
  和项目根一份 `mgh-sdr-<分支名>-<时间戳>.md`(人读报告)。
- **新建(临时)**:`.mgh-sdr/.active` 标记文件——运行期间存在、跑完自动删。作用:告诉随包
  安装的运行纪律守卫「评审进行中」,防止其它 AI 会话乱写你的项目。
- **不改**你的任何业务代码,不碰 `openspec/`,不删任何东西。

## 怎么跑

### 推荐:一条命令(launcher)

```bash
py <安装目录>/mgh-core/scripts/mgh_sdr_launch.py --repo <项目绝对路径> --base master
```

它会自动:检查宿主(opencode/claude)→ 投影检查基线 → **在外部前端仓做受控检索**(如果你的
安全设计里写了前端仓地址)→ 写运行标记 → 拉起宿主会话执行评审 → 跑完删标记 → 你去项目根看报告。

多分支定时检查:

```bash
py mgh_sdr_launch.py --repo <项目> --multi-branch branches.txt   # 每行一个分支名,# 注释
```

### 外部仓授权(首次运行会问一次)

**现象**:如果你的存量安全设计里引用了外部前端仓,首次评审时流程会停下来问你:「这个
外部目录还没授权,是否允许检索?」逐仓一个绝对路径。

**原因**:声明了外部仓 ≠ 自动放行。评审要不要去**另一个项目目录**翻代码,由你拍板——
只有你同意、写入项目里授权配置(只读清单 `<repo>/.mgh/read-roots.json`)的外部仓才会被
检索。未经授权的仓零读取、直接跳过,进「待批清单」。

**改法(二选一)**:

- **同意** → 让会话执行一次(每仓一条;脚本会打印变更,写完以后每次评审直接生效,不再问):

  ```bash
  py <安装目录>/mgh-core/scripts/read_roots_config.py --target <项目绝对路径> --add <外部仓绝对路径>
  ```

  然后**重跑刚才那条评审命令**(同参数),新授权立刻生效。
- **拒绝** → 什么配置都不会写,流程降级继续(该仓零读取);报告会如实标注「外部仓未授权,
  前端相关检查面未覆盖」。

**日常管理**(要就单独跑,平时不用管):

```bash
py <安装目录>/mgh-core/scripts/read_roots_config.py --target <项目> --list    # 看已授权了哪些
py <安装目录>/mgh-core/scripts/read_roots_config.py --target <项目> --check   # 体检(有失效路径会报)
py <安装目录>/mgh-core/scripts/read_roots_config.py --target <项目> --remove <路径>   # 收回授权
```

### 备选:在宿主会话里直接敲 `/mgh-sdr`

功能等价。唯一区别:外部仓检索发生在宿主会话内,**可能弹一次**权限确认(诚实告知)。加
`--help` 参数运行可看参数表。

### 评审耗时长 / 疑似卡住怎么办

- 接口多的分支,逐单元评审以小时计是正常的(慢 ≠ 挂死)。宿主运行日志(stderr)持续打印
  心跳行(`inflight=<k> unit=<id> idle=<s>s stall_window=<w>s done=<d>/<total>`,`idle` = 该
  子评审已静默秒数,`stall_window` = 它这次被判定的静默窗口——有这个数才看得出 `idle` 离被
  杀还有多远)。
- 某个子评审**卡死不动**(静默超过失活阈值 `--stall-timeout-s`,默认 15 分钟)或单任务超时
  (`--call-timeout-s`)→ 派发器自动结束该子评审的进程树(含其派生的子进程)并**自动重派**;
  每个非正常结束的单元都会留运行留痕 `.mgh-sdr/runs/<时间戳>/markers/sdr/<单元名>.run.log`
  (该次输出的最后一段),排查卡死原因先看它。跑批汇总里 `stall_killed` 列出被这样救活的单元。
  这里「静默」指**两条输出流都没新内容**(任一在写就不算静默),免得把全程不写标准错误的子评审
  误判成卡死。另外派发器给每个子任务开了**独立会话**:在终端按 Ctrl-C 中断派发器时,不会连带
  掐掉在跑的子评审——派发器退出前会自己逐个结束它们(正常中断不留残余);只有被系统**硬杀**时
  才可能留下残余,用 `--kill-stale` 清理。
- **「长时间没输出」不等于「卡住了」——派发器会自己放宽,你也可以关掉它**:在限流网关上,
  子评审静默的常见原因是这次调用**正排在网关队列里等**,本地看不出区别(一样零输出)。所以
  派发器只把静默当成「这个槽位空等太久了」的上界,而不是「这个子评审坏了」的判决。它会
  **自我纠正**:一旦出现「某个单元因静默被杀、之后**在同一次运行里**重派跑完」——「刚才那次
  静默其实不致命」的硬证据——派发器立刻把**本轮生效的静默窗口翻倍**并在运行日志里报一行
  (`stall window widened 900s -> 1800s`),其后派发的单元按放宽后的值判定;上限是单任务硬超时
  (`--call-timeout-s`)的 0.8 倍,不会无限放宽,同一个单元无论被杀几次只计一次证据。也可以
  直接把这条判据**整个关掉**:加 `--stall-timeout-s 0`(此时「一轮跑多久必须收敛」只由
  `--call-timeout-s`(单任务硬超时)一个人管,宿主驱动的跑批建议同时把它调小一点)。每次退出时,
  汇总里还会给出本轮**已完成单元
  的耗时分布**(`runtime_p50_s`/`runtime_p95_s`/`runtime_max_s`;本轮没有单元完成时这三项不
  出现)与被杀单元烧掉的槽位秒(`stall_killed_slots_s`/`stall_killed_slot_pct` = 占本轮并发
  容量的百分比)。
- 反复重派毫无进展 → 「零推进熔断」:连续两轮检查没有任何单元完成就主动停止(报 `stalled`
  + 卡住单元清单 `stalled_pending[]`),防无限烧钱的保护——按提示诊断,**不要盲目重跑**。

### 配额限流网关下的自动防护(人话版)

内网 AI 网关**按调用次数限流**(如每 10 分钟 100 次)时,逐单元评审可能撞上「快败风暴」:
配额一耗尽,子评审秒级报错退出 → 立刻排队重派 → 再撞配额,几分钟烧光整轮调用。派发器内置
三层防护 + 一个人工重派口,通常无需你做任何事:

| 机制 | 什么时候生效 | 你会看到什么 |
|---|---|---|
| 快败冷却(`--cooldown-s`,默认 300 秒) | 短时间内(2 分钟窗口)连续 3 个以上子评审秒级失败回队 → 暂停派新任务等一会儿;在跑的不受影响;等待按剩余时间预算自动截短 | 日志 `cooldown #1 …pausing NEW dispatch`;汇总 `cooldowns` 计数 |
| 限流风暴截断(默认开) | 连续多个失败单元输出尾部都带限流特征(`429`/`rate limit`/`quota`)且数量达到 `--wave` → 立即停止派发退出(退出码 2),汇总 `rate_limited:true` + 单元清单 | 日志给出「等满一个配额窗口再重跑」提示;确认配额耗尽时快速止损 |
| 零推进熔断前的最后退避 | 熔断停止前若时间预算还够,自动做**一次**「冷却 → 重新盘点磁盘 → 再看」;有进展撤销熔断继续跑,仍零进展才停 | 日志 `pre-breaker backoff`;单次运行最多一次,不会无限等 |
| 失败单元人工重派(`--retry-failed`,默认关) | 某单元明确回「失败」且运行留痕呈网关瞬断形态 → 编排器**至多一次**带 `--retry-failed` 重跑(自动删失败标记、按原身份重派) | 汇总 `retried_failed` 计数;再失败接受缺口并在报告 degraded 披露 |

**取值参考**:`--stall-timeout-s` 默认值按实测标定,口径是「**已完成单元**耗时的 p99 × 2,
向下取整到分钟,且不低于 900 秒」(代入样本 n=84:p50 134 / p95 229 / p99 325 秒 → 900 秒)。
该样本只含**活下来**的单元(因排队被杀的那批天然不在内),所以它说明「健康单元到这儿为止」,
**不等于**「超过它就该杀」——设小了会误杀慢任务,重派更浪费;限流环境失活阈不建议低于
600 秒,或干脆用 `--stall-timeout-s 0` 关掉。`--call-timeout-s` ≥ 实测单元耗时 p99 的 3–5 倍;
`--wave` ≈ 配额每分钟上限 × 0.8 ÷ 每单元每分钟呼叫数(向下取整);`--time-budget-ms` = 宿主
单次调用超时 × 0.8。

## 它检查什么(默认 6 个维度)

| 维度 | 一句话 |
|---|---|
| 垂直越权 | 新接口没配权限就能访问? |
| 横向越权 | 查询没按机构/用户隔离,A 能看 B 的数据? |
| 其他权限 | 匿名可达、会话处理、白名单绕过? |
| SQL 注入 | 字符串拼 SQL、`${}` 插值? |
| 敏感信息 | 返回值/日志带敏感字段没脱敏? |
| 输入校验 | 新入参没做长度/格式/枚举校验? |

可用 `--dimensions` 收窄或追加自定义检查项。

## 报告怎么读

项目根的 `mgh-sdr-<分支>-<时间戳>.md`:头部是分支/时间/检查面;正文按维度列问题(每条含
严重度、接口路由、文件行号、风险、建议、命中的存量规矩);然后是「无问题单元」清单(这些
接口可以放心合);最后是诚实边界。**报告里的问题全部是 AI 候选,合码前必须人工复核**,不是
确认漏洞。

## 已知边界(诚实告知)

- 接口识别靠注解猜(Spring/JAX-RS/Servlet 常用注解):没猜到的接口不会漏掉,会退到「按目录
  打包」的粗粒度单元一起查;纯非 Java 项目也能跑,只是全部走粗粒度。
- 检查基准(存量设计)太长会按优先级截断(接口授权 > SQL > 输入校验 > 敏感数据),低优先级
  细节可能没进基准——报告会标注。
- 外部仓的结论是**检索那一刻的快照**,不保证前端分支已同步;前端仓**不可达**或**未授权**
  时流程照跑,但前端相关检查面没覆盖——报告会区分标注是哪种(不可达 / 未授权)。
- 敏感字段清单:项目里配了就用项目的;没配就回退到内置默认模板(37 项,比其它命令的默认收窄更宽,
  因为代码复核漏检代价更高)——报告会标注用的是哪个来源。
