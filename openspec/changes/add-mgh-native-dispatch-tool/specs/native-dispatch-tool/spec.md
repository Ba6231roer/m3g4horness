## Purpose

为原生子代理派发提供进程内确定性执行面:插件自定义工具 `mgh_dispatch` 按计划工件在宿主进程
内并发创建、驱动、收割子会话(一次工具调用跑完全部波次,零 LLM 波次回合),派发语义与宿主内
置子代理工具对齐;令牌展开钩子把任务引用从长路径收敛为「计划引用 + 短号」。自身零标记写入、
零 findings 解读——判定单一来源保持在磁盘标记与 Python。

## ADDED Requirements

### Requirement: mgh_dispatch 工具的注册与输入契约

独立插件文件 SHALL 于 `setup` 内注册自定义工具 `mgh_dispatch`(注册被 `await`),输入
schema(闭集字段):`plan`(计划文件引用,接受绝对路径或相对项目根的路径——插件位置即项目
根锚;这是输入中**唯一**允许路径形态的字段)、`wave`(可选整数 = 只跑该波)、`units`(可选
短号数组 = 只派指定单元;缺省 = 按计划顺序跑全部波次)。工具 SHALL NEVER 接收任何单元的任
务文件路径、产物路径或标记路径(这些一律来自计划工件)。输入校验失败——计划不可读/不可解
析、短号不在计划内、`units` 与 `wave` 同传、`wave` 越界——SHALL 以工具错误 + 一句 recipe
fail-loud,且 NEVER 创建任何会话。

#### Scenario: 项目相对计划引用与单波模式

- **WHEN** 编排器调用 `mgh_dispatch {plan: ".mgh-sdr/runs/<run>/native_plan.json", wave: 3}`
- **THEN** 插件以项目根解析该引用、读计划,只派第 3 波单元——模型输出里除这一个计划引用外
  不出现任何路径

#### Scenario: 未知短号 fail-loud 且零会话

- **WHEN** `units` 含计划外短号(错抄形态)
- **THEN** 工具错误 + recipe(合法短号清单来源指引),本调用未创建任何子会话——错抄在
  spawn 前被收口

#### Scenario: 冲突输入拒识

- **WHEN** 同传 `wave` 与 `units`
- **THEN** 工具错误 + recipe(二者互斥)——歧义输入不猜测

### Requirement: 派发语义与内置子代理工具对齐

`mgh_dispatch` 创建子会话的每个环节 SHALL 与宿主内置子代理工具语义对齐,缺一即缺口:

1. **权限断言**:每次创建前对 `subagent` 动作按目标 agent 断言(与内置工具同动作);
2. **深度限制**:沿父链累计嵌套深度并按宿主深度上限拒绝(编排器→子代理单层为默认合法形
   态;插件自身作为工具调用运行在编排器会话内,其创建的子会话深度 = 编排器深度 + 1);
3. **primary 模式拒绝**:计划携带的 agent 名 SHALL 在创建前校验为 subagent 形态孪生,
   primary 模式一律拒绝并报 recipe(需各 tier 的 subagent 形态定义);
4. **任务消息构造**:`description` = 单元短号;任务消息 = 该单元任务文件内容**逐字**(插
   件读文件注入,模型与编排器零撰写);
5. **波次执行**:波内并发 = 计划 `wave_size`,波间顺序执行,前波全部终态后才开下一波。

#### Scenario: 单波内并发与波间顺序

- **WHEN** 计划两波各 3 单元,调用缺省全跑模式
- **THEN** 第 1 波 3 个子会话并发创建并全部终态后,第 2 波才创建——与既有波次屏障纪律同
  形,且全程零 LLM 波次回合

#### Scenario: 权限断言逐 spawn 执行

- **WHEN** 企业权限配置对 `subagent` 动作设为拒绝
- **THEN** 工具在创建第一个子会话前收到断言失败,以工具错误返回 recipe——插件不绕过权限
  层,也不代答

#### Scenario: primary 模式 agent 被拒

- **WHEN** 计划携带的 agent 为 primary 形态(误用子进程派发孪生)
- **THEN** 创建前拒绝 + recipe(指出需要 subagent 形态孪生)——NEVER 降级尝试或静默换名

### Requirement: 收割分类、幂等与标记真相源

每单元收割 SHALL 以**磁盘标记**分类:完成标记在场 = `done`;失败标记在场 = `failed`;会话
终态但无标记 = `no-marker`(如实上报,NEVER 代写标记、NEVER 推断成败)。工具 SHALL 幂等:
重复调用跳过已有终态标记的单元(只派无标记者)。工具内 SHALL NOT 重派(无标记单元如实报
告;重试 = 编排器再调用一次工具,由幂等性收敛)。返回值 SHALL 为紧凑结构化摘要:各分类计
数 + `failed`/`no-marker` 的短号清单 + 每单元会话 id + 实跑波次;SHALL NEVER 携带 findings
内容或任务文本(详情在盘上,防摘要膨胀编排器上下文)。

#### Scenario: 幂等重入零重派

- **WHEN** 首次调用后 3 单元 done、1 单元 no-marker,编排器再调用一次
- **THEN** 第二次只派那 1 个无标记单元,3 个终态单元零重派——重试机制即幂等重入

#### Scenario: 无标记如实上报且不代写

- **WHEN** 某子会话终态但磁盘无任何标记
- **THEN** 摘要中该单元为 `no-marker`,磁盘标记零变化——标记唯一写者保持是单元自身执行
  纪律

#### Scenario: 摘要紧凑不含 findings

- **WHEN** 一波 5 单元全部完成
- **THEN** 摘要为计数与短号/会话 id 级结构,不含任何 findings 字段或任务文本——编排器上下
  文只进摘要不进详情

### Requirement: 取消级联与配额自限

**取消级联**:工具调用被中止(宿主中止信号)时,SHALL 对其创建且仍活跃的全部子会话逐个中
断后再结束——NEVER 留下孤儿子会话继续烧配额。**配额自限**:项目根环境画像含配额参数时,
波间派发 SHALL 按「窗口内已派单元数 × 每单元调用估算 + 估算 ≤ 窗口上限」的既有算术自限
(估算口径与子进程派发器一致);余量不足 SHALL 等待窗口滚动再派下一波(等待事实计入工具返
回摘要)。画像缺省/无配额参数时零节流。**有界性**:全部波次模式 SHALL 以计划波次数为上界
(每单元至多被本工具派发一次),NEVER 形成无限循环。

#### Scenario: 中止级联

- **WHEN** 全部波次模式执行到第 2 波时编排器会话被中止
- **THEN** 第 2 波仍活跃的子会话被逐个中断,工具结束;第 1 波已完成单元的标记不受影响

#### Scenario: 配额自限等窗

- **WHEN** 画像配额 100 次/600 秒、每单元估算 10 次,第 1 波 3 单元后窗口余量不足再派一波
- **THEN** 工具等待窗口滚动后才创建第 2 波会话,摘要记录等待事实——超大扇出不会一波打穿
  配额

### Requirement: 令牌展开钩子消除长路径转述

同一插件 SHALL 注册 `execute.before` 钩子,对内置子代理工具调用的任务文本做令牌展开:任务
文本首行形如令牌行「计划引用 + 短号」(固定可识别前缀)时,钩子读计划、按短号取该单元任务
文件内容,**将任务文本整体替换为文件内容**(内置子代理工具收到的是全文,模型转述零路径);
非令牌形态的任务文本 SHALL 原样放行(不干扰普通子代理用法)。令牌行中的短号不在计划内、计
划不可读/不可解析 → 工具错误 + recipe(fail-loud,子代理不启动)。展开后的任务文本与计划
物化产物逐字一致(同一文件来源)。sdr 原生波次纪律 fragment 的任务中继行 SHALL 切换为令牌
形(该钩子的首个消费者;纪律语义不变,仅引用形态从任务文件路径换为令牌行)。

#### Scenario: 短号进、全文出

- **WHEN** 编排器以令牌行(计划引用 + `sdr-k3f7`)调用内置子代理工具
- **THEN** 钩子将其展开为该单元任务文件全文后放行,子代理读到的任务与计划物化产物逐字一
  致;编排器输出中无长任务路径

#### Scenario: 非令牌文本零干扰

- **WHEN** 用户或其它流程以普通文本调用内置子代理工具(无令牌前缀)
- **THEN** 钩子原样放行——展开只认固定前缀的令牌形态,不是通用改写器

#### Scenario: 未知令牌 fail-loud

- **WHEN** 令牌行短号不在计划内(错抄形态)
- **THEN** 工具错误 + recipe,子代理不启动——错抄在 spawn 前收口,与工具输入校验同一防线

### Requirement: 分发面与形状自检

派发插件 SHALL 为独立文件(守卫插件零触碰),安装器 SHALL 从「单文件名」扩展为「固定文件
集」(守卫 + 派发两文件,幂等放置,仍 NEVER 触碰用户其它插件),install 自检清单同步。CI
源码形状锚 SHALL 覆盖:工具注册被 `await`、权限断言/深度/模式拒绝三分支、取消级联分支、短
号校验分支、令牌展开分支(固定前缀常量)在场——移除任一分支即 fail-loud;守卫插件既有形
状锚不受影响。

#### Scenario: 安装器固定文件集

- **WHEN** `install.sh --opencode` 执行
- **THEN** 目标项目插件目录同时存在守卫与派发两插件文件(幂等重装一致),用户其它插件零
  触碰

#### Scenario: CI 形状锚防分支漂移

- **WHEN** 派发插件源码被改动致任一安全分支(断言/深度/模式拒绝/级联)缺失
- **THEN** 形状锚测试 fail——「漏一项即安全缺口」的清单由 CI 机器化守卫

#### Scenario: 令牌展开前缀常量锚定

- **WHEN** CI 检查插件源码与 sdr fragment
- **THEN** 两者引用同一固定令牌前缀常量(或同形字面量),前缀漂移即 fail——钩子与消费者
  的契约不靠口头约定
