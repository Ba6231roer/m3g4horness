# mgh-\* 使用遥测接口文档（服务端实现依据）

> **受众**：人类——内网遥测服务端的实现者。本文档自包含，不需要读 m3g4horness 仓的其他文件。
> **版本**：v1（2026-10-14）。客户端（m3g4horness 工具族侧）按本文档发送；服务端按本文档接收即可，实现技术栈不限。

## 一、背景：这是什么接口

m3g4horness 是一套装进企业内网项目、由 AI 编程 agent 执行的安全工作流工具族，所有命令以 `mgh-` 开头（如 `mgh-init`）。工具的部署方（运维）想统计「谁在用、用了哪些命令、用得频不频」。

为此，每条 `mgh-*` 命令在**启动时**向内网遥测服务上报一条使用记录。本文档定义这条上报的 HTTP 接口。

**上报是尽力而为的**：客户端发完就不管了（不发重试、不排队、不缓存）。网络不通、服务端报错、超时，客户端都直接放弃这一条并继续正常工作。所以服务端不需要为可靠性做任何设计——**收到就入库，丢了无所谓**。

## 二、先解释几个词

| 词 | 意思 |
| --- | --- |
| 遥测（telemetry） | 软件运行时把「谁在用、用了什么」这类使用事实上报给服务端的行为 |
| 埋点 | 在程序流程里预先安插好的上报调用点（本接口的客户端埋点在各命令的启动步骤） |
| 端点（endpoint） | 服务端提供的一个网络地址（URL），客户端往它发请求 |

## 三、接口定义

- **方法**：HTTP `POST`，一次一条记录。
- **路径**：由部署方自定，建议 `/api/mgh-telemetry`。最终以完整 URL 配置给客户端（见第六节）。
- **请求头**：`Content-Type: application/json; charset=utf-8`（正文含中文，必须按 UTF-8 解析）。
- **请求体**：单个 JSON 对象，字段**恰好六项**，不多不少：

| 字段 | 类型 | 含义 | 示例 |
| --- | --- | --- | --- |
| `username` | string | 触发命令的本机登录名。客户端已去掉 Windows 域前缀（`DOMAIN\zhangsan` 只留 `zhangsan`）；采集不到时为字面量 `unknown` | `zhangsan` |
| `ip` | string | 客户端按本机路由表选出的、到服务端会走的出口 IP。可能是 `127.0.0.1` 或 IPv6 形态；采集不到时为 `unknown` | `10.20.30.40` |
| `operation` | string | 命令的中文名，取值是闭集（见下方对照表）；若客户端收到未知命令则回退为其原名 | `项目安全设计初始化` |
| `method` | string | 命令原名，`mgh-xxx` 形态、不带斜杠 | `mgh-init` |
| `params` | string | 用户执行该命令时的原始参数，原样记录；超过 500 字符客户端截断；无参数时为空串 | `--scope payment --resume` |
| `time` | int | **恒为 10，请忽略其语义**。此字段是服务端历史遥测记录表早就存在的列（原用于耗时秒数），本工具不计时，为兼容表结构固定填 10 | `10` |

**operation 闭集对照表**（客户端与服务端共用这套值）：

| method | operation |
| --- | --- |
| `mgh-init` | 项目安全设计初始化 |
| `mgh-sdr` | 安全设计复核 |
| `mgh-sra` | 需求安全增强 |
| `mgh-srr` | 需求安全评审 |
| `mgh-sast` | 静态安全扫描 |
| `mgh-ut-init` | 测试约定初始化 |

## 四、响应要求

- **2xx**（200 / 201 / 204 皆可）即视为上报成功。响应体客户端不读，建议返回 `{"ok":true}` 便于人工 curl 调试。
- **4xx / 5xx / 连接失败 / 超时**：客户端静默丢弃该条，不重试。因此服务端对轻微异常（如偶发内部错误）不必设计补偿——丢了就丢了。
- **处理要快**：客户端总超时只有约 2 秒，超时即弃。建议服务端「先落盘、后处理」，尽快返回 2xx。

## 五、客户端行为（服务端据此设定预期）

- **上报时机**：每条命令在启动路径的确定性脚本内部上报，用户每启动一次 `mgh-*` 命令（含 `--resume` 断点续跑、会话中断后重入）产生一条记录。
- **去重口径**：客户端用 30 分钟冷却窗口近似「会话切分」——同一件事的反复内部查询不会重复上报；但**统计口径请理解为「活动窗口开始次数」**，不是严格的会话数：超过 30 分钟的长耗时任务中途查询会多计一条，30 分钟内的快速重启会漏计，两条误差都正常。
- **多分支**：mgh-sdr 一次多分支扫描会对每个分支各报一条（每条分支复核是真实的独立工作单元），事件数会多于用户启动次数，属预期。
- **覆盖范围**：当前接入 mgh-init / mgh-sdr / mgh-sra / mgh-srr / mgh-ut-init 五条命令；mgh-sast 暂未接入（后续版本补充），收到的 method 不会超出第三节对照表。
- **频率量级**：每人每天每命令几次到几十次，单条小于 1KB。不需要批量接口、不需要高并发设计。
- **网络路径**：客户端绕过 `http_proxy`/`HTTPS_PROXY` 等代理环境变量直连，内网可达即可。建议服务端提供**内网 http** 端点，或证书有效的 https（客户端不对自签证书做特殊处理，自签 https 会导致发送失败——失败即弃，不影响工具，但收不到数）。
- **鉴权**：v1 无鉴权，依赖内网位置隔离。若日后需要 token，会在请求头扩展，服务端预留即可，本期不用做。
- **前向兼容**：客户端目前严格发六字段；服务端解析时建议**忽略未知字段**，这样将来加字段不用改服务端。

## 六、客户端配置（供运维参考）

- 端点通过环境变量 `MGH_TELEMETRY_URL` 配置（值为完整 URL，如 `http://telemetry.internal:8080/api/mgh-telemetry`）。
- 环境变量与客户端内置默认常量**都没配时，客户端完全不上网**（工具装完默认就是这种惰性状态）。
- 服务端就绪后：把 URL 交给 m3g4horness 维护者写进客户端内置默认常量（一行改动），或在各台机器设置该环境变量，二选一。

## 七、请求示例

```bash
curl -X POST http://telemetry.internal:8080/api/mgh-telemetry \
  -H "Content-Type: application/json; charset=utf-8" \
  -d '{"username":"zhangsan","ip":"10.20.30.40","operation":"项目安全设计初始化","method":"mgh-init","params":"--scope payment","time":10}'
```

## 八、存储建议

| 字段 | 建议列型 |
| --- | --- |
| `username` | UTF-8 变长文本（如 VARCHAR(100)） |
| `ip` | 字符串（要兼容 `unknown` 与 IPv6，不要用原生 IP 类型） |
| `operation` | UTF-8 变长文本（如 VARCHAR(100)） |
| `method` | 变长文本（如 VARCHAR(50)） |
| `params` | UTF-8 变长文本（至少 VARCHAR(500)，客户端保证 ≤500 字符） |
| `time` | 整型（沿用历史表的既有耗时列，本工具恒为 10） |

另建议服务端自行加一个接收时间戳列（客户端不带上报时刻，以服务端接收时间为准）。
