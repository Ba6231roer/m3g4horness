## Context

现状与约束(动机见 proposal「Why」;前五个 change 已归档,主规格含 native-dispatch-core /
native-dispatch-watchdog / security-design-review 原生形态):

- 宿主 2.x 插件 API(源码核对 + 本机 2.1.0 实测):promise 形插件的 Context 含
  `tool.transform`(注册自定义工具,`probe_echo` 实测可被模型调用)、`session` 域(全量:
  create/get/prompt/wait/context/interrupt 等——进程内创建并驱动子会话的全部原语在
  场)、`permission.assert`(与内置工具同动作断言)、`agent` 域(agent 信息可查);工具执行
  上下文带 `signal`(中止信号)与 `progress`。自定义工具返回结构化 Result。
- 内置子代理工具的语义清单(对齐基准,源码核对):`subagent` 动作权限断言、沿父链深度计
  数对 `experimental.subagent_depth`(默认 1)拒绝、primary 模式 agent 拒绝、前台
  `jobs.block` 阻塞/后台通知、被中止时级联中断子会话。
- 计划工件契约(已归档,只读消费):`native_plan.json` 含 `{v, tier, agent, repo,
  wave_size, wave_size_source, units_total, waves[]}`,每单元 `{id(短号), unit_id,
  task_file, checkpoint_path, done_marker, …枚举器字段}`;`--check` 幂等校验。
- 守卫插件(block_adhoc_scripts.ts)刚经历两次 change(2.x 迁移 + 权限闸门),稳定性面宝
  贵;安装器现契约「只管一个插件文件名」。
- sdr 原生波次纪律 fragment 的中继行现行形态:description = 短号;任务体 = 固定句 +
  `task_file` 绝对路径。
- 约束:R2 零依赖(插件仅宿主 API + node 内建);R5.5 措辞纪律;R5.10 分发纯净;
  R5.11(SDD 产物不引本仓私有文档路径);版本矩阵 = 本机 2.1.0 实机 + 企业 2.0.32 探测。

## Goals / Non-Goals

**Goals:**

- 数百至上千单元场景的原生派发零 LLM 波次回合(一次工具调用跑完计划)。
- 派发语义与内置子代理工具零缺口(断言/深度/模式/级联)。
- 模型输出中的长路径面收敛为「每次调用一个计划引用 + 短号」;令牌展开钩子让通道 A(内置
  子代理工具路径)也零长路径。
- 胶水纯度:判定(标记/计划/画像)全部来自磁盘,插件零标记写入、零 findings 解读。

**Non-Goals:**

- 不改四个基础件脚本(计划/画像/看门狗只读消费;需要计划字段扩展时按「可选字段、旧计划
  仍过 --check」另议)。
- sdr 不切换到本工具(维持通道 A + 令牌展开;本工具的首个真实消费者是 init,第 7/8 个
  change)。
- 不做工具内重派、限流特征判定、失败原因分类(收敛纪律留编排层;摘要只报事实)。
- 不动 claude/dsh 面;不做 Form/MCP 面处置(看门狗职责)。

## Decisions

### D1 独立插件文件,守卫插件零触碰

- **决策**:新文件 `releases/opencode/plugins/mgh_dispatch.ts`;安装器从单文件名扩为固定
  文件集(守卫 + 派发)。
- **理由**:守卫插件是安全防线,刚经历两次迁移,再混入派发工具会弄脏其「THIN SHIM / glue
  only」的单一身份与既有形状锚;派发工具是独立关注点(执行面而非拦截面),独立文件让两
  者的测试、purity、演进互不牵连。宿主对插件目录自动发现,两文件并存零接线成本。
- **备选否决**:并入守卫插件(身份混杂,锚面互扰);拆成第三个插件文件专门放令牌展开钩
  子(钩子与工具同源同计划读取,拆开徒增文件与自检面)。

### D2 输入契约:计划引用是唯一路径字段(对「永不收长路径」的一条受控例外)

- **决策**:输入 schema = `plan`(必填,绝对或项目相对路径)+ `wave`/`units`(可选,互
  斥);单元级路径(任务文件/产物/标记)永不入参,一律取自计划。
- **理由**:工具必须定位计划,完全无路径输入不可行(运行目录发现有歧义);把路径面压缩到
  **每次调用一个字段**,且接受项目相对形(计划物化的 stdout 摘要可输出相对形,转述面比绝
  对路径短一个量级);单元级长路径(数量大、每次调用都出现)才是错抄主力,已全部消除。
- **备选否决**:工具自行发现最新 run 的计划(多 run/多分支歧义,静默选错比显式传引用危
  险);`units` 收任务文件路径(回到 P4 主力风险面)。

### D3 语义对齐:断言/深度/模式拒绝逐项复刻,深度上限读取保守缺省

- **决策**:每次创建子会话前 `permission.assert`(subagent 动作,资源 = 目标 agent);沿
  `parentID` 链累计深度,超过宿主深度上限即拒绝;创建前校验 agent 模式非 primary。深度上
  限的配置读取若插件面不可达,保守缺省 = 宿主默认值 1(编排器→子代理单层恰为合法形态,
  缺省不误伤)。
- **理由**:内置工具的这三道闸是权限/安全边界,插件绕过任一即开洞;深度上限读不到时取
  「与宿主默认一致」的保守值,行为与默认配置下的内置工具等价,过度严格仅影响显式调深度的
  非默认场景(如实披露)。
- **备选否决**:信任服务端兜底(深度/模式检查是客户端前置,服务端不重复拦,漏检即静默放
  行);省略权限断言(闸门 change 刚把 ask 关掉,插件必须走同一条断言链而不是自辟蹊径)。

### D4 无工具内重派:幂等重入即重试机制

- **决策**:工具对每单元至多派发一次;无标记单元如实报 `no-marker`;重试 = 编排器再调用
  一次(标记感知跳过终态)。「至多一轮重派」的收敛纪律留在编排层(framework/壳),与通道
  A 同一纪律。
- **理由**:工具内重派会把「重试几轮」的策略判定带进 TS,违背判定单一来源;幂等重入让重试
  语义与通道 A 完全同构(编排器一次决策、一次调用),且每次调用都是可审计的独立事件(摘要
  落编排器上下文)。
- **备选否决**:工具内自动重派 no-marker 单元一轮(策略入胶水,两处纪律);工具内无限重试
  (显然否)。

### D5 配额自限:复用既有估算算术,画像在项目根可直读

- **决策**:波间按画像配额做准入(窗内已派单元 × K + K ≤ N,K = 每单元调用估算,口径与
  子进程派发器一致),余量不足睡等窗口滚动;等待事实进摘要。画像从 `<项目根>/.mgh/
  env-profile.json` 直读(插件已持项目根),缺省/无配额零节流。
- **理由**:超大扇出正是配额敏感场景,工具跑全部波次时若不自限会一波打穿窗口(其后的失败
  会以 no-marker 形式回灌编排器);算术与估算口径复用既有实现语义,不造第二套口径。节流是
  「等待」而非「判定」——磁盘参数驱动,胶水不做策略。
- **备选否决**:节流留给编排器(全部波次模式下编排器没有波间回合,无处插手);精确计数
  (插件看不到子会话内部调用数,估算口径是既有既定语义)。

### D6 令牌展开钩子 + sdr fragment 中继行同步换形

- **决策**:同一插件注册 `execute.before` 钩子:识别固定前缀的令牌行(计划引用 + 短号),
  按计划展开为任务文件全文后放行内置子代理工具;未知短号 fail-loud。sdr fragment 的中继行
  从「固定句 + task_file 绝对路径」切换为「固定句 + 令牌行」(一行级改动,纪律语义不
  变)。
- **理由**:这是 sdr 接入 design 预留的 P4 残余清零手段;钩子与工具同文件、同计划读取邏
  辑,拆开是重复;fragment 换形让钩子落地即有真实消费者,不是存货。展开后子代理收到的任
  务与计划物化产物逐字同源(同一文件),构造保证不变。
- **备选否决**:仅做校验不做展开(校验需解析计划定位单元,成本与展开相同,收益更低);
  fragment 保持路径形态(钩子无消费者,P4 残余继续挂账)。

### D7 收割只认磁盘标记;摘要紧凑防上下文膨胀

- **决策**:单元分类 = 磁盘标记三分(done/failed/no-marker);会话终态仅用于判定「可以查
  标记了」,不参与成败判定;摘要 = 计数 + 短号清单 + 会话 id,绝不携带 findings/任务文本。
- **理由**:标记是唯一真相源(全路线一致不变量);全部波次模式的摘要会被弱模型读进上下
  文,大扇出下逐单元详情会复刻「摘要膨胀」老问题——摘要只给「下一步该干什么」所需的最小
  事实,详情永远在盘上。
- **备选否决**:按会话 outcome 分类(第二真相源,与标记不一致时无仲裁);摘要携带 findings
  计数之外的内容(膨胀面)。

## Risks / Trade-offs

- [插件 API 处于 2.x 演进期(session 域/工具注册面 churn)] → 锁宿主版本;形状锚 + 双版
  本闸门;契约版本矩阵记录 2.0.32 差异。
- [深度上限配置在插件面不可达(缺省 1 兜底)] → 行为与默认配置等价;如实披露;若后续版本
  暴露配置读取再对齐(Open Question)。
- [全部波次模式运行很久,工具调用长时间阻塞编排器回合] → 这是设计本意(零 LLM 波次);
  编排器/看门狗仍可中止它(取消级联);摘要落上下文一次而非数百次。
- [令牌展开钩子与未来宿主侧 subagent 工具改动冲突(工具更名/字段变化)] → 钩子按固定前缀
  识别令牌行、非令牌零干扰;工具名变化只影响「对哪个工具挂钩」,形状锚随版本更新。
- [计划引用相对形解析锚 = 插件位置(项目根)] → 与守卫插件的锚点注入同源;多
  location/worktree 场景按各自 location 解析,与既有锚语义一致。
- [两个插件文件的 purity/契约面翻倍] → 任务含 purity + contracts + 安装自检;文件集固定
  两个,不发散。

## Migration Plan

1. 实现插件(工具 + 钩子)+ 安装器扩展 + fragment 换形;形状锚先红后绿。
2. 本机 2.1.0 实机闸门(小计划全链/幂等/级联/未知短号/令牌展开);企业 2.0.32 只读探测
   (交接)。
3. 合入随 install 分发;回滚 = 安装器回退单文件集 + 删插件与测试(fragment 换形可独立回
   退)。
4. 第 7/8 个 change(init 接入)为本工具接入首个大规模消费者。

## Open Questions

- 宿主深度上限配置在插件面是否可达(当前按不可达设计,保守缺省 1)——双版本闸门顺带确
  认;可达则对齐读取。
- 计划物化的 stdout 摘要是否补一个「项目相对形计划路径」字段方便转述(可选字段,旧计划仍
  过 --check)——倾向在第 7 个 change(init 接入)一并评估,本 change 不改基础件。
