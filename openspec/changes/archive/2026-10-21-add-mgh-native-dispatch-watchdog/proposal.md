> **人话序** 现象:无人值守跑长任务时,子代理可能以几种方式「卡住不走」——等一个没人会去点的
> 授权框、发起一个没人会去答的问询、或者干脆活着但半天没有任何进展;这些卡住在宿主里都没
> 有超时,上一次权限闸门 change 把「弹问」在产生前关掉了,但闸门管不到的面(另一套问询机
> 制、真挂死、活着不收敛)仍会让整个 run 停摆到有人回来看。根因:原生派发没有「进程树可杀」
> 这种外部控制面,需要一个**独立于编排会话**的观察者,在旁边盯着运行树的会话状态,发现卡住
> 就动手处置。改什么:新增一个确定性看门狗脚本——读本机服务注册文件连上正在跑的宿主服务,
> 圈定「本次 run 的根会话及其全部后代」为唯一作用域,周期性巡检;发现等待授权/问询的,替
> 无人值守的用户回一句「拒绝+怎么做」;发现超时无进展或超总时长的子会话,中止它(中止后
> 单元自然回到待办重派);所有动作留痕落盘,破坏性动作支持先审后动。怎么验证:假服务全链
> 测;实机复现「等待授权」「无进展」两种卡住形态,看门狗处置后父会话继续、单元回待办;圈
> 外会话绝不被碰。

## Why

- 原生(同宿主服务)派发下,runner 时代的「字节静默检测 + 进程树杀」控制面不存在了:子代理
  会话挂在宿主服务进程里,编排器(弱模型)既看不到它卡了、也杀不掉它;权限闸门(上一
  change)消除了「弹问」的主力来源,但其规格自己披露了四类管不到的残余(Form/MCP 问询、
  provider-executed 工具、无断言自定义工具),且「活着不收敛」从来不是权限层能治的病。
- 宿主 2.x 提供了完备的进程外观测与处置面:服务注册文件(地址+本机密码)是官方发现契约,
  HTTP API 可枚举会话树(按父 id)、查活跃集、查等待中的授权/表单、查消息时间戳,并可回
  复授权、取消表单、中止会话——这些已在 2.1.0 实机验证可用,无需新建任何宿主面。
- 看门狗必须独立于编排会话存活(编排器自己挂住时恰恰最需要它),又必须严格圈定作用域
  (宿主服务是共享的,用户自己的其它会话绝不能被碰)——这两个约束决定了它是「常驻外部脚
  本 + 父子树所有权校验」的形态,而不是插件内定时器(随服务死锁一起死)或波次边界脚本
  (前台子代理阻塞父会话时,波次边界根本到不了)。
- 这是原生派发路线的第 4 个 change(共 8 个):插件迁移、权限闸门、计划物化已归档;看门狗
  就位后,sdr 才具备无人值守接入条件(第 5 个)。

## What Changes

- **新增** `core/scripts/native_watchdog.py`(确定性叶脚本,零依赖,仅标准库 HTTP 客户端,
  只连本机回环地址):
  - **服务发现**:默认读 `[XDG_STATE_HOME 或 ~/.local/state]/opencode/service.json`(含地
    址、本机密码),`--service-json` 可覆盖;鉴权失败/连接丢失时重读注册文件(服务重启后
    密码会换);**只接受回环地址**(127.0.0.1/localhost/::1),NEVER 连非本机服务。
  - **作用域圈定**:根会话 = `--root` 显式值 > 环境变量 `OPENCODE_SESSION_ID`(宿主 shell
    工具自动注入);按父 id 递归收集全部后代构成「运行树」;**每次动作前重新校验目标会话
    仍在树内**,树外会话 NEVER 被读状态以外的任何操作触碰;根会话不存在 → 退出码 2。
  - **周期巡检**(`--poll-s` 缺省 15 秒;`--once` 单扫模式供波次边界/测试用):对树内每个
    会话采集——活跃态、等待中的授权请求、等待中的表单问询、最近持久进展时间(会话更新时
    间/最新消息时间/工具执行时间的最大值)。授权与表单请求自身不带时间戳,由看门狗以
    「首次见到」时刻起算宽限。
  - **动作阶梯**(全部受 `--dry-run` 先审后动约束):
    ① 等待授权超宽限(缺省 90 秒)→ 回复「拒绝 + 一句替代做法提示」——**永不**回复「批
    准」;② 等待表单/问询超宽限 → 取消并附提示;③ 后代会话超静默窗(缺省 20 分钟,不低
    于宿主流超时+重试余量)或超单元总时长(缺省 60 分钟)→ 中止该会话(中止后其挂起工具
    与后台 shell 随宿主作用域连带收口);④ 中止后仍不落定 → 复核窗后再中止一次,仍不落
    定记「未收口」;⑤ 根会话自身的静默/超时**默认只记录不中止**(`--interrupt-root` 显式
    opt-in)——中止根会话会连带取消整波在飞子代理,是最后手段。
  - **标记纪律**:看门狗**永不**写任何单元完成/失败标记(磁盘标记的唯一写者保持是单元自
    身的执行纪律);被中止的单元因无标记自然回到待办重派,「至多重派几轮」的收敛闸属于
    编排纪律(下一个 change),不属于看门狗。
  - **工件与退出**:动作与观测事件追加 `<run>/watchdog/events.jsonl`,树快照原子写
    `<run>/watchdog/state.json`(传 `--run-dir` 时;缺省不落盘只出摘要);stdout 恰好一行
    JSON 摘要,stderr 心跳行;退出码 0(树已落定/预算耗尽干净收尾)、2(存在未收口挂死/
    服务不可达/根缺失,需要人)、1(误用)。常驻模式自退:运行树落定(根与全部后代空
    闲、无等待项)或 `--deadline-s` 预算到点;**永不**自动重启宿主服务(共享服务,重启是
    人的决定,只记录建议)。
- **契约**:`core/contracts/fanout/runtime.md` 增「native watchdog」节(发现/作用域/阈值表/
  动作阶梯/工件与退出码/非目标)。
- **非目标**:不做单元身份映射与失败标记代写(会话级处置,单元级归编排纪律);不直接管理
  shell API(中止会话已连带收口其 shell);不自动重启服务;不做限流/配额判定(决策留在计
  划器与编排纪律);不接入任何命令壳(sdr 接入是下一个 change);不动 claude/dsh 面。
