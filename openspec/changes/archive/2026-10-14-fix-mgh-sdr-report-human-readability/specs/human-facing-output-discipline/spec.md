## Purpose

管住一件事：凡是「人会去读的产物」，不许出现只有本工具研发者才懂的词和句式。过程文档
（命令壳、stage 提示词、契约、中间产物）继续按上下文预算保持紧凑，不在本能力辖内——
本能力治理的是**出口**，不是过程文风。

## ADDED Requirements

### Requirement: 人类面表面登记与校准读者

用一张登记表管理「人要读的产物」，登记制：哪个命令想纳入本纪律，就在它自己的 change 里
给登记表加一行；没登记的命令不受辖制。每行写清三件事：所属命令、表面（哪个产物文件或
文档区段）、受众类别（纯人类面，或双受众——双受众的接入时 SHALL 声明以哪面为主、另一面
如何取舍）。

所有登记表面共用同一个**校准读者**画像：有一两年 Java Web 开发经验的工程师——懂目标仓
的日常词汇（Mapper/DAO/注解/接口/SQL），懂安全常用词（越权、SQL 注入、脱敏、白名单；
生僻缩写首次出现配一句白话解释），但**不了解本工具的内部概念，也没读过本仓任何文档**。
一个词能不能出现在登记表面上，以这个画像能不能顺读为准。

机器面数据文件的字段名与枚举值、agent 面过程文档，都不在辖内。

初版登记（随本 change 建立）：

| 命令 | 表面 | 受众类别 |
| --- | --- | --- |
| mgh-sdr | HTML 报告全文（标签、表头、图例、披露、正文） | 纯人类面 |
| mgh-sdr | `sdr_report_data.json` 中直接给人读的文本字段（`risk`/`suggestion`/`repro`/`fix_diff`） | 纯人类面 |

#### Scenario: 登记表随命令接入而增长

- **WHEN** 某个 change 把 mgh-init 的 AGENTS.md 受管块作为双受众表面接入本纪律
- **THEN** 该 change 在登记表加一行（写明受众类别与双受众取舍策略），本能力各项要求对
  新增的行立即生效；没登记的命令产物始终不受辖制

#### Scenario: 过程文档不在辖内

- **WHEN** 某个分发的 stage 提示词内部使用「扇出」「切片」「hunk」等紧凑表述
- **THEN** 不算违例——过程文档的紧凑性是上下文预算下的产品特性，本能力治理出口、不治理
  过程文风

#### Scenario: 用校准读者画像判定词汇

- **WHEN** 某登记表面的人类面文本里出现「以任一有效登录会话 POST /user/del 传他人 id，
  他人记录会被删除」和「该接口存在 IDOR（水平越权：能拿到别人的数据）」
- **THEN** 两条都合规：前者是现象直述，后者是安全常用词加首现白话；若出现「路由锚」「基线
  投影」则违例（见「内部词汇闭集与出口守卫」要求）

### Requirement: 内部词汇闭集与出口守卫

**内部词汇** = 只有读过本仓文档的人才懂的词。全部收在一份单一真相源模块里：
`core/scripts/human_face_vocab.py`，内容是一份词表常量加一个扫描函数（输入一段文本，
返回命中的词）。只用 Python 标准库、零运行时依赖、无命令行入口。词表按两层组织：

- **核心词表**（全工具族通用，10 词条）：投影、切片、hunk、扇出、物化、待办壳、facet、
  闭集、vvah、vvaharness。每个词条 MUST 附「人话替身」——改写确定性文案与读者评审共用
  的翻译指引（如 投影 →「按预算截取/只带了一部分」）。
- **域补充词表**（只在该命令域作术语，按域分组）：sdr 的路由锚、向上锚定、锚定单元、
  目录聚簇、判不穿、残余归并、链合并、检查面，及概览分类语境的 interface / standalone；
  其他命令域（init / ut-init / sra / sast / srr）的补充词由初始采集预置为数据，登记该域
  表面时激活（守卫不扫未登记表面，预置零副作用）。

初始词表来自本 change 附带的全局评审（三个分域评审子代理通读全部命令域的人类面产物与
高渗出源，定稿记录随本 change 归档）；此后词条增长的唯一入口是显式加一行，来源 = 读者
评审建议 + 维护者人工发现，经维护者确认后录入，每次改词表 SHALL 同步更新内容锚测试
（改词不改测试 = 红）。

**同形词守则**（词表维护的硬规矩）：同形不同义的词 MUST 按域归组收精确词形，NEVER 收
单词做子串禁。红灯样本：「锚点」（证据锚点——`文件:行` 格式的出处指针）是产品概念，
「锚定到需求条目」是正常动词；只有 sdr 的「路由锚/向上锚定/锚定单元」是分组算法词，
若按「锚定」子串禁会误杀两者。同理处理过的还有 基线/单元/哨兵/存量/簇（单词一律不收，
复合词形按域收）。

守卫分两面，宽严刻意不同：

- **确定性文案面**——代码里写死的报告字符串（标签、表头、图例、披露、模板文本）SHALL
  零命中闭集（核心 + 该表面所属域的补充词），用回归测试强制：命中即测试失败、CI 拦截。
  这是实现缺陷，没有借口。
- **模型文本面**——LLM 产出的字段文本，在产出链末步的确定性校验（渲染器/校验器的
  `--check` 面）里扫描；命中 SHALL 只在 stderr 打计数告警（写明字段名和命中的词），
  SHALL NOT 改变退出码，SHALL NOT 改写或删除命中文本。理由：模型措辞是软质量，既不能
  因为它卡死一个跑完的长流程，也不能静默篡改模型结论。

闭集 SHALL NOT 收录安全常用词与目标仓技术词（误伤读者的工作语言）、报告结构章节名
（属信息架构决策，不属词汇问题）、中文工程圈通用词（靠读者评审兜底）。

#### Scenario: 确定性文案命中闭集被测试拦截

- **WHEN** 渲染脚本某个人类面字符串常量含补充词「向上锚定」，回归测试对全部确定性文案
  做闭集扫描
- **THEN** 测试失败（fail），发布被 CI 拦截

#### Scenario: 模型文本命中闭集只告警、不阻断、不改写

- **WHEN** 某份 draft 的 `risk` 文本包含核心词「投影」，末步校验扫描到它
- **THEN** stderr 输出至少一条计数告警（含字段名与词），退出码与没有该词时相同，报告
  文本逐字保留

#### Scenario: 词表单一真相源，两个消费方同源

- **WHEN** 检查末步校验与回归测试的闭集取值来源
- **THEN** 两者 import 同一个模块常量，全仓不存在第二份词表副本

#### Scenario: 词表增长必须带上测试锚

- **WHEN** 维护者向词表新增一个词条（来源：评审建议或人工发现）但没更新内容锚测试
- **THEN** 内容锚测试失败，提醒补锚；补齐后该词即被两面守卫永久拦截

### Requirement: 登记表面的读者模型写作纪律

给登记表面产出文本的 stage 提示词（任务模板/agent 定义）SHALL 携带一小节**紧凑的**写作
纪律（这段文字随任务消息逐单元消耗，字数受控并过预算 lint），至少说清：读者是谁（校准
读者画像）；风险类文本第一句写现象（谁、从什么入口、传什么参数 → 发生什么），技术根因
放后面；能落到具体接口/方法调用的问题要给复现方式；改动只有一两处代码的修复要给修改
前后对比；人类面字段禁用闭集词（提示词护栏为主，确定性兜底见出口守卫）。

上述结构 SHALL 落成产物 schema 里的**可选字段**（复现方式、修复对比等，按表面适用性
裁剪）：结构比措辞约束可靠——字段在，模型就得按字段的形状写；字段缺席（本 change 之前
的旧数据）就省略展示，流程与校验都不失败。

任务模板里**输出字段的描述文字本身 SHALL 用校准读者的语言书写**：模型会模仿字段描述的
语域，描述写「首句写现象：谁、经什么入口、传什么 → 发生什么」，模型就写人话——这是
防止上下文污染的最高杠杆点。

#### Scenario: 接入命令的任务模板携带纪律与结构字段

- **WHEN** 检查某个已登记命令的 fan-out 任务模板与三面 agent 定义产物文件
- **THEN** 模板含写作纪律节和承载新结构的可选字段 schema 示例；输出字段描述文本自身零
  闭集词；三面 agent 定义与之一致（确定性文档面，机器可对账）

#### Scenario: 旧数据缺结构字段时安静降级

- **WHEN** 本 change 之前产出的旧 draft 没有复现方式/修复对比字段
- **THEN** 渲染省略对应展示，流程与校验不失败（登记表面的向后兼容义务）

### Requirement: 读者模拟评审（拦新造词）

词表拦不住模型临场发明的词（全项目从未出现过、本次输出新造的名词堆叠）。对此用一次
专门的 LLM 评审兜底：产出链末步，对登记表面的人类面文本跑一次**有界的读者模拟评审**——
评审 subagent 按校准读者画像通读这些文本，列出「读不懂或需要项目背景才能懂」的词与句，
产出一份建议清单（advisories：词/句 + 所在字段 + 一句为什么难懂）。确定性渲染把清单
展示为报告内**默认折叠**的「可读性自检」小节，并在 stderr 报一条计数。

约束：

- **尽力而为**：评审没派发、跑挂了、产出为空或不可解析，SHALL 只让「可读性自检」小节
  省略——报告本体完整、流程不失败、退出码不变；评审缺席 SHALL NOT 影响 resume 收尾。
- **只建议不改写**：评审输出 SHALL NOT 改动任何产物正文。
- **建议词是闭集增行的候选**：经维护者确认后才进词表（防止评审误报直接污染闭集），进入
  即被出口守卫永久拦截——这是「发现 → 沉淀」的增长闭环。
- **有界**：评审输入 = 渲染器产出的文本束（仅人类面文本字段），评审回传有界 ack，不回显
  正文。

#### Scenario: 评审建议渲染为折叠小节

- **WHEN** 评审 subagent 产出建议清单（如：词「落库链路」在 P-03 的 risk 里，一两年经验
  读者不懂），渲染器随后重渲染
- **THEN** 报告出现默认折叠的「可读性自检」小节列出该建议，stderr 报一条计数；正文任何
  字段未被改动

#### Scenario: 评审缺席报告仍完整

- **WHEN** 评审 subagent 未派发或失败，run 目录没有可解析的建议文件
- **THEN** 报告没有「可读性自检」小节，其余内容与退出码和正常完成时一致

#### Scenario: 建议词经确认进入词表

- **WHEN** 维护者在评审报告里两次看到同一个建议词，确认它是真内部词
- **THEN** 维护者向 `human_face_vocab.py` 加一行（同步更新内容锚测试），此后该词被确定性
  扫描与末步告警两面拦截
