> **人话序** 现象：`/mgh-sdr` 把每个变更单元切成一个"切片"文件交给复核子代理。切片按字节预算打包，但打包用的是**近似值**（各文件 diff 正文长度之和，每文件外挂 64 字节余量），而子代理真正读的是**渲染后的切片文件**——它还要写文件清单、注解上下文块、符号表，以及每个 hunk 一行的定位头。两者不同源，于是有两条漏网路径：① 多文件单元"近似没超、渲染超了"，今天没有任何检查，原样发给子代理；② 兜底规则规定单个超大文件不切两半，于是"这个文件自己的改动就超预算"时，它仍然原样发出。`/mgh-init` 刚修过一模一样的坑：当时聚合层也是"单个类目超预算就照发、只打一行警告"，结果是一次真实的"请求上下文过大"把整个单元跑崩；当时的解法是先在物化层做一次确定性的字段瘦身投影，瘦身后仍超预算就报错退出、一个单元都不发。根因：切片预算被当成"尽量满足的软目标"，而大模型上下文窗口是物理硬上限，软目标在硬顶面前等于没有。改什么：把闸门从近似值移到**渲染后的实测字节**，并给超预算三级处置——① 多文件单元超了就按既有贪心规则**再切一次**（无损：单元变多，内容一份不丢）；② 只剩单个文件、且上下文块是超出的主因时，截掉描述性的注解上下文/符号表（diff 正文、文件清单、定位头与一切证据锚点绝不截，截断痕迹在切片里可见并记入产出）；③ 瘦身仍超预算则退出码 2、零派发，打印超预算单元与字节数。怎么验证：构造多文件超预算的 diff，确认被切成多个都 ≤ 预算的单元且内容无丢失；构造单文件超预算的 diff，确认要么带可见截断标记地发出、要么退出码 2 且没有任何子代理被派出；预算内的 diff 输出与改动前逐字节一致。

## Why

- **闸门与产物不同源。** 打包期的成员大小是估算的：`diff_group.py` 对 standalone 目录簇用 `_cluster_standalone._size`、对 interface 成分用 `_con_bytes → _sel_hunks_size`，两者都只数 diff 正文行长度、每文件加 64 字节常数余量；而物化出去的切片由 `_render_slice` 生成，还要加头部、文件清单、注解上下文块、符号表，以及**每个 hunk 一行**的 `@@ <path> @@ new-file lines N+C` 定位头。多 hunk 文件上这 64 字节余量根本盖不住这些开销，因此"估算 ≤ 预算而渲染 > 预算"是真实存在的状态——**且从未被检查**。现有单测 `test_interface_budget_splits_parts` 里 `unit_bytes > 2048 + 1024` 那句容差就是这个缺口的化石：它默认了实测可以比预算大 1KB 而仍然放行。
- **单文件超预算路径无任何告警或拦截。** 源码自承："one oversize file may still exceed it (merged-capped, never split mid-file, same rule as standalone)"。接口维度的"单成分超预算就在它的文件间再切"同样以文件为不可切单位。于是**单文件 diff 字节数 > `--max-standalone-bytes` / `--max-interface-bytes` 时，切片必然超预算，且既不告警也不拒绝**。
- 这与 `harden-mgh-init-t2-oversize-shard` 废除的那条被容忍的缺口**逐字同形**：当时聚合契约写着"不能再切、仍会发出（部分受限）"，其后果是一次真实的请求上下文过大崩溃（400KB 输入）让整个 T2 单元退出 1。该 change 的结论是：预算违约不能靠"警告 + 照发"，必须"先确定性瘦身，仍超则 fail-loud 零派发"。
- 现状并非完全无防线：`fanout_runner` 已能在子代理崩溃后把 stderr 尾部匹配到上下文超限签名并附 `reason:context-overflow` 与可操作 recipe；它也已在枚举脚本退出 2 时原样 `sys.exit(2)`。但前者是**事后诊断**（单元已经烧掉配额、崩溃、留下无标记待办），后者才是本 change 想前移的闸门位置。
- **sdr 可瘦身的字段比 init 少，这一点必须诚实。** init 侧 T1 记录有 `description`/`usage`/`protects`/`gaps` 等大段散文可截；sdr 切片的主体是 **diff 正文**，那是复核的事实依据，绝不能截。sdr 上真正可截的只有两块**上下文**：interface 单元的注解上下文块（含未变更路由方法片段——它是越权面的锚点，须谨慎且有界）与 codegraph 模式下 java 残余簇的符号表（每文件最多 40 行，但单元内文件数不设限，大簇下可达数十 KB）。因此本 change 的承重半边是**把闸门落到实测字节**，瘦身只是原子残渣的有限救援，不指望它承担主要压力。

## What Changes

- **测量下沉为单一真相源**：新增一个"渲染某单元 → 取 utf-8 字节数"的测量函数，与物化共用同一个渲染函数（**NEVER** 另写一套估算逻辑）。打包期的成员大小改用该实测值：standalone 目录簇"合并到实测 ≤ 上限为止"，interface 成分打包同样按实测贪心——既有"排序确定性"与"**不切文件中部**"两条规则不变。
- **超预算三级处置（严格按序，前者可解则不进下一级）**：
  1. **无损重切**：多文件单元实测超预算 → 按既有贪心规则再切续单元（`unit_id` 沿用 `-partN` 形态，`chain[]` 随每一份续单元走，与既有规则一致），每份续单元实测 ≤ 其适用上限。**SHALL NOT 丢 hunk、SHALL NOT 截内容**——单元数增加是唯一代价。
  2. **上下文瘦身**：仅当单元**已不可再切**（单文件原子残渣）且仍超预算时，对该单元的描述性上下文块按确定性上限截断（字符串与列表两种形态都要处理）。**证据锚点 MUST NOT 被截断**：diff 正文、文件清单、hunk 定位头、以及被下游校验器检查的字段全部保留。截断 MUST 在切片内可见（如 `… (截断:K 行 / 原 N 字节)`），被截字段与原始字节数 MUST 记入产出。
  3. **fail-loud 零派发**：瘦身后仍超预算 → 退出码 2，stderr 报出超预算单元的 `unit_id`、适用上限、实测字节数与最大贡献文件；**在写出任何切片或待办清单之前判定**（零副作用——`fanout_runner --tier sdr` 已对枚举脚本退出 2 原样透传，不会有任何子代理被派出）。
- **不重写中间层产物**：瘦身只作用于面向子代理的那一份切片投影；`grouping.json` 既有字段、已通过 `--check` 的记录 MUST NOT 被就地改写。
- **不新增 flag**：真正的调节杆仍是既有的 `--max-standalone-bytes` / `--max-interface-bytes`；两级内部上限为模块常量（镜像 init 侧"不给 CLI 契约面加表面积"的取舍）。
- **披露**：超预算命中（重切 / 瘦身）MUST 进入 `grouping.json`（新增顶层预算记录与每单元瘦身痕迹）、`--check` 断言（字段存在时校验，旧产物跳过）与最终报告的诚实边界声明，**不允许静默降级**。
- **默认关、通路不变**：预算内单元的输出 MUST 与改动前逐字节一致（切片文本、`pending[]` 既有字段、退出码、stderr 既有行），作为可证伪的无回归线。
- **非目标**：不改 `--max-standalone-bytes` / `--max-interface-bytes` 的默认值；不改分组算法（排除过滤器、调用链锚定、目录聚类规则）；不靠 `git diff -U0` 之类重渲染缩减 diff 上下文；不动 `-partN` 命名；不给 `/mgh-init` 或其他命令做同样的事。
