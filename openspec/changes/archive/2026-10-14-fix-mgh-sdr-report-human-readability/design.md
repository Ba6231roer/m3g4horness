# design — fix-mgh-sdr-report-human-readability

## 背景

动机和全局症状见 proposal 的 Why，这里只讲约束。硬约束有两条：目标用户场景的 150K 上下文
预算不可变，所以 agent 面过程文档必须继续紧凑——**不治理过程文风**；报告是自包含单文件
HTML（零外部依赖）、模板的动态文本全部走 textContent 注入（防注入路线不动）、数据文件与
HTML 内嵌数据 JSON 等价、旧数据向后兼容。取证样本：springBootTemplate 2026-10-13 dry-run，
22 条问题记录。

## 全局分析：五个污染入口 + 全家族的「人读面」清单

「难读」不是单一根因，是五个独立入口叠加——只堵一个会被其余四个绕过：

| # | 入口 | 是怎么回事 | 对策 |
| --- | --- | --- | --- |
| P1 | 确定性层自带 | 渲染脚本把算法术语硬编码进报告标签（实测「路由锚 4、向上锚定 2、捕获调用边 107」印在 `render_sdr_report.py` 里，不是模型写的） | 文案平实化 + 回归测试锁住 |
| P2 | 模型复读输入词汇 | 语言模型的输出锚定输入 token：任务消息被内部名词泡透、又没有反向指令时，回声进人类字段是默认行为 | 写作纪律（反向指令 + 读者画像）+ 输出字段描述本身用读者语言 |
| P3 | 结构缺失 | 人类内容只有自由散文字段，「复现方式」「修复前后对比」没有地方放——渲染层想展示也无米下锅 | schema 加可选结构字段（结构比措辞约束可靠） |
| P4 | 出口无守卫 | 没有任何确定性检查点扫人类面文本的措辞 | 末步 `--check` 告警 + 确定性文案测试 fail |
| P5 | 双受众未区分 | AGENTS.md 类产物同时服务 agent 和人，没人声明以哪面为主，结果按 agent 密度写 | 登记表声明受众类别（扩展期解决） |

「人要读的产物」全家族盘点如下。本次只接入第一行，其余逐命令接入：

| 命令 | 人读面 | 受众 | 接入状态 |
| --- | --- | --- | --- |
| mgh-sdr | HTML 报告；数据文件里给人读的文本字段 | 纯人类面 | **本次** |
| mgh-sast | 报告与详述文件 | 纯人类面 | 未接入 |
| mgh-sra | 评审报告 | 纯人类面 | 未接入 |
| mgh-srr | 报告 + 台账 | 纯人类面 | 未接入 |
| mgh-init | 目标仓 AGENTS.md 受管块 + `docs/security-controls/*.md` | 双受众 | 未接入（扩展期） |
| mgh-ut-init | AGENTS.md 受管块 + `docs/test-conventions/` | 双受众 | 未接入（扩展期） |

（机器面 JSON 的字段名、枚举值一律豁免；agent 面过程文档一律豁免。）

一句话版本的核心洞察：**污染不发生在「文档写得难读」，发生在「agent 面词汇无翻译地流进
人类面字段」。所以治理单位是人类面出口的词汇与结构——出口做翻译，过程保持紧凑。**仓库
的受众声明制（R3）早就把产物分了人类面/agent 面，缺的是执行机制。

## 治理模式：三层防线 + 一个增长闭环

针对「已知内部词」和「模型临场新造词」两类威胁（后者是硬编码词表天然拦不住的），防线
分三层，外加一个让词表随时间变强的反馈环：

- **第一层·写时预防（降低产生概率）**：可选结构字段逼着模型按字段形状写（复现方式就得
  写「怎么调、传什么、看到什么」）；任务模板里输出字段的描述文字本身用读者语言写——
  模型模仿字段描述的语域，这是防污染的最高杠杆点；再加一节紧凑的写作纪律。
- **第二层·已知词确定性拦截**：词表单源模块；代码写死的文案命中 → 测试 fail；模型文本
  命中 → 末步 stderr 告警（不阻断、不改写）。
- **第三层·新造词读者评审**：每次运行在报告产出后追加一次有界的 LLM 评审，按校准读者
  画像通读问题文本，列出读不懂的词句，建议清单渲染成报告里默认折叠的「可读性自检」小节。
- **增长闭环（发现 → 沉淀）**：评审建议的词和维护者人工发现的词，经确认后向词表加一行
  （同步改内容锚测试），从此被第二层永久拦截：

```mermaid
flowchart LR
    R[报告/人类面文本] --> S["第二层:确定性扫描<br/>(已知词闭集)"]
    R --> V["第三层:读者模拟评审<br/>(拦新造词,LLM)"]
    V --> A["可读性自检小节<br/>(报告内折叠展示)"]
    A --> M["维护者确认<br/>(防评审误报直接进词表)"]
    M -->|加一行 + 改测试锚| W[词表 human_face_vocab]
    W --> S
```

诚实的边界：第三层本身也是 LLM，可能有漏报和误报，所以它只出建议、不阻断、要经维护者
确认才沉淀——它是「把维护者从逐字通读里解放出来」的助手，不是最终裁判。

## Goals / Non-Goals

**Goals**：建跨命令能力规格（登记制）+ 词表单源模块 + 读者评审机制——模式的规范锚点与
基础设施；mgh-sdr 首落地（确定性文案平实化、复现/修复对比结构、写作纪律、出口扫描与
评审、旧数据零破坏）。

**Non-Goals**：过程文档人化（预算取舍，不碰）；sast/sra/srr/init/ut-init 接入（后续逐命令
立项）；报告信息架构与样式改版；diff 语义高亮。

## Decisions

### D1 治理出口，不治理过程

见核心洞察。备选「把过程文档改得人也能读」被否：与 150K 预算直接冲突，且受众声明制下
agent 面本不该迁就人类读者。

### D2 模式的规范锚点 = 新能力规格，登记制

跨命令规则（闭集、画像、守卫、评审、纪律）如果每个命令的 spec 各写一份，扩展期必漂移。
新能力 `human-facing-output-discipline` 承载通用要求 + 登记表；各命令 spec 只持自己的字段
级/渲染级要求并引用闭集。登记制（接入一个登记一个）保证规格**只描述已实现的行为**——
不会出现「规格说 SHALL 而全家只有 sdr 实现了」的假账。备选「只写进 design 当方法论」
被否：扩展期没有规范锚点，每个命令的 change 都得重新论证一遍。

### D3 词表单源模块 + 初始全量采集 + 增长机制（回答「硬编码词怎么迭代」）

词表放 `core/scripts/human_face_vocab.py`：一份词表常量 + 一个扫描函数，零依赖、无 CLI
入口（不进契约 lint 的 flag 对账面）。两个消费方——末步校验（告警）与回归测试（fail）——
import 同一常量，全仓没有第二份词表副本；这承了 `sdr_tier.py`「一个谓词、写读两端同源」
的先例。

**初始词表不是拍脑袋**：propose 阶段用三个并行评审子代理做了全量采集（sdr 域渲染层/
契约/提示词；init/ut-init 域装配脚本与输出规范；sast/sra/srr 域报告与壳），定稿见本
change 的 `vocab-candidates.md`（核心 10 词条 + 按域补充词 + 候选池存档）。这次采集立刻
修正了两个错误：①「锚定」原被放进了核心集，采集证明「锚点/证据锚点」是产品概念、sra
里「锚定到需求条目」是正常动词——只有「路由锚/向上锚定/锚定单元」是 sdr 算法词，必须
按域收精确词形；②抓到实锤：上游代号「vvaharness」已经印在 SAST 报告页脚（人类面实际
泄漏）。同形词守则（单词一律不收、复合词形按域收）由此写进能力规格。

增长机制：词表只拦已知词，**它靠反馈环变长**——候选来源是第三层评审的建议和维护者的
人工发现，入口只有一个：显式加一行（含域归属与人话替身），且必须同步改内容锚测试（改词
不改测试 = 红）。这和仓库 purity allowlist 的「只经显式增行增长、测试防陈旧」是同一个
模式。不设自动收录：评审是 LLM、有误报，误报词进了闭集会误伤真文本，所以必须人确认。
整表重扫不常规做；某域接入时按同一方法对该域再做一次分域评审即可。

### D4 sdr 确定性文案平实化 + 折叠诊断明细

分组概览改成「评审分组：6 个接口单元、2 个独立文件单元（共 8 个）」+「调用链分析：启用
——4 个变更接口作为分组入口、2 处改动挂接到未变更接口、1 组同链合并」；调用边计数这类
分组质量信号收进 `<details>` 默认折叠的「分组诊断」明细。数据文件的 `grouping`/计数字段
一个不动（机器面零感知）。诚实边界 ①–⑦ 语义逐条保留、措辞转述（例：⑤「基线经字节预算
投影」→「存量设计参考按优先级截断：优先保留 接口授权 > SQL > 输入校验 > 敏感数据，低
优先级细节可能未完整包含」）；排除/失败/截断披露同治。备选「数字从人类面删掉」被否：
信息有损失；折叠已经解决默认视图的噪音。

### D5 新字段形态：`repro` 字符串 + `fix_diff` 数组，均可选

`repro` 是单个字符串（「怎么调 + 传什么 + 看到什么」），不拆成结构化三字段——弱模型对
多字段结构的漂移率高，字符串加一个形态示例最稳。`fix_diff` 是 `[{before, after}]` 数组
（1–2 组），`before` 从 slice 里逐字摘原文，`after` 写改后的样子；不用统一 diff/patch 格式
——模型写 diff 语法容易错且没法逐字校验，前后块对比对读者零学习成本（这正是用户原始
诉求）。兼容：全部可选，旧 draft 没有就省略展示（和「draft 缺 line 降级」同一哲学）；
`--check` 的数据↔HTML 等价校验自动覆盖新字段。

### D6 渲染形态：修改前/修改后上下堆叠代码块

问题卡片：复现方式一行文本；修复对比每组两块上下堆叠的 `<pre>`（「修改前」/「修改后」
标签，等宽字体）。不用左右并排——窄屏和打印场景会横向溢出。代码文本走 textContent
注入（模板既有防注入路线，`</script>`/`<!--` 的转义由 `_json_embed` 继续覆盖）；数据文件
`findings[]` 带原字段，HTML 与 JSON 同源。

### D7 两面扫描的宽严：确定性面 fail、模型面 warn

代码写死的字符串命中闭集是实现缺陷，单测 fail、CI 拦。模型文本命中只告警不改码：渲染
是长流程的最后一步，模型措辞是软质量——fail-loud 会把跑完的 run 卡死在最后一步，重试
成本全量；仓库哲学本来就是「硬边界（路径/依赖）才 NEVER，软质量走提示词 + 可见性」。
备选「render 时自动剥离命中词」被否：静默篡改模型结论。

### D8 读者模拟评审（回答「拦不住新造词怎么办」）

机制：渲染顺带写 `<run-dir>/readability_text_bundle.json`（全部人类面文本字段的单一
文本束）；编排器在首次渲染后派发**一次**有界评审 subagent（任务模板
`core/prompts/fragments/fanout/readability-review.md`：读文本束 → 写
`readability_advisories.json` → 回传单行 ack）；编排器再调一次渲染（幂等原子覆盖），
渲染发现建议文件就把 `readability[]` 并进数据文件、把「可读性自检」小节并进报告。
不走 fanout_runner（它是 per-unit 波次派发器，这是一次性单调用）；不新增 CLI flag
（两个文件都走 run 目录约定路径，和 grouping.json 的自动搭载同款）；成本 = 每 run 一次
有界调用，对照 8–40 次单元调用可以忽略。

约束：尽力而为——评审缺席（未派发/失败/产出坏）只少一个小节，报告完整、退出码不变、
resume 照常收尾；只建议不改写；建议词经维护者确认才进词表。为什么用 LLM 做这件事：
「这段话一两年经验的读者能不能懂」是判断类工作，恰恰是本仓「机械重活下沉脚本、判断
交给 LLM」哲学的正牌用例；确定性代码做不了未知词检测（零依赖前提下没有分词与词频库）。

### D9 提示词纪律的承载与字数预算

`sdr-task.md` 增量控制在约 15 行：纪律四条 + schema 扩两个字段，合并进既有「Draft
schema」节；输出字段描述改用读者语言（`risk` 的括注从「简体中文风险描述」改成「第一句
写现象：谁、经什么入口、传什么 → 发生什么」）。三面 agent 定义只改 Output schema 行 +
一句纪律指针。该文件随每单元任务消息消耗（一个 run 8–40 个单元），字数就是调用成本，
完成后跑 `tools/check_distributed_prompt_budget.py`。契约 `core/contracts/sdr/pipeline.md`
同步。评审模板 `readability-review.md` 同为分发面（三面镜像随 install 拷贝，无 agent
定义克隆——它由编排器直接派发，不经 fanout_runner，所以不需要三面 agent 定义同步，但
三面 mgh-sdr 壳的流程清单要加这一步）。

### D10 存量测试锚更新

`tests/test_render_sdr_report.py:385` 断言「向上锚定 8」等存量锚随改写更新为新措辞锚；
新增禁词守卫测（提取渲染脚本全部人类面字符串常量 + 模板文本节点，全量扫闭集——漏改
即红）、新字段渲染测、兼容降级测、文本束/自检小节测；新增 `tests/test_human_face_vocab.py`
（闭集内容锚 + 双端同源 import + 改词不改测试 = 红）。`check_contracts` 面零变化（无
flag 增删）。

### D11 扩展期的双受众张力（mgh-init 等，预案、不在本 change 实现）

init/ut-init 的 AGENTS.md 受管块同时服务 agent（按需加载的索引）和人（通读约定）。接入期
的取舍预案：受管块保持紧凑**索引**但语言平实（条目名/路径是给机器的锚，说明短句是给人
的）；解释性内容放 `docs/security-controls/*.md` 详述文件（人类面正文，完整纪律适用）；
rules 产出的 stage 提示词带同款纪律。届时若「紧凑索引」仍需要个别内部词，由登记行的取舍
策略声明豁免面——登记制就是给这种局部妥协留的显式出口。

### D12 SDD 工件自身的可读性

本次回应的另一个问题：openspec 工件此前沿用 agent 面压缩文风，维护者评审吃力。已按
「SDD 工件按人类可读写作」规则（已写入仓库 AGENTS.md 的 R3，只约束增量）重写本 change
全部工件；主规格的**存量段落**在 delta 里逐字保留原文，不回溯改写——重写 120 行密集
规范文本的风险是语义漂移，存量可读化留给将来专门的规格人化 change（逐 requirement 重写
+ 语义对照）。

## Risks / Trade-offs

- [闭集误伤合法文本] → 闭集只收流水线专属词；「单元」「基线」「维度」不进核心集（sdr
  概览只禁 interface/standalone 两个英文分类词）；守卫测用真仓报告语料回归对照。
- [弱模型给不出 repro/fix_diff 或形态漂移] → 字段可选不 gate 流程；纪律段附形态示例
  锚定；`--check` 告警给可见性；报告横幅本就声明「LLM 候选」。
- [`fix_diff.before` 与 slice 失真（模型转写）] → 纪律要求逐字摘原文；渲染不做一致性校验
  （校验需要读 slice，违反渲染器只读 run 目录的边界）；已知残余，人工复核兜底。
- [确定性文案改写漏网] → 守卫测是全量提取扫描（非逐个断言），漏改即红。
- [提示词增量推高 per-unit 成本] → D9 的字数上限 + budget lint。
- [读者评审误报/漏报] → 只建议不阻断；建议要经维护者确认才进词表；评审缺席零影响。
  它是助手不是裁判，残余靠人工复核（与「LLM 候选」总边界一致）。
- [评审子代理自己读不懂纪律/越界读] → 模板里写死只读文本束一个文件 + 单行 ack 回传，
  与 sdr-task.md 同款硬边界句式。

## Migration Plan

无数据迁移：新字段全可选，旧 draft/旧数据文件照常渲染；`--check` 语义不变（增告警不改
退出码）。回滚 = revert 单提交。扩展到下一个命令 = 新 change（登记表加行 + 该命令 spec
增量 + 五件套按表面裁剪），不改本 change 产物。apply 时按仓库惯例 bump VERSION +
CHANGELOG。
