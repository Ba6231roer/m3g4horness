## Context

`/mgh-sdr` 的单元输入是 `diff_group.py` 物化的一份只读切片文件，由 `_render_slice(repo, base, branch, unit, raw_text)` 生成；子代理读它，复核判断全部落在它身上（见 proposal.md · Why）。

现状的两处要害，都是"判据与产物不同源"造成的：

| 环节 | 判据 | 产物 |
| --- | --- | --- |
| standalone 目录簇归并 | `_cluster_standalone._size` = Σ(每 hunk 行 `len(l)+1`) + 64/文件 | `_render_slice` 输出 |
| standalone 残余(带 hunk 选择)归并 | `_cluster_standalone_sel._size` → `_sel_hunks_size` | 同上 |
| interface 成分贪心打包 | `_con_bytes` → `_sel_hunks_size`（成分大小）；成分内再切用 `_sel_hunks_size` | 同上 |

渲染体比估算体多出：头部 5 行、每文件一行清单、注解上下文块、符号表块、**每个 hunk 一行**定位头、结尾收束行。估算只给每文件留 64 字节常数余量，多 hunk 文件上盖不住。

约束（承 AGENTS.md R5 族，实现时须遵守）：脚本零运行时依赖、自定位、utf-8、任意 cwd、stdout=JSON / stderr=诊断、退出码 `0/1/2`、`--help` 即契约面（承 R5.1/R5.3）；不新增 flag 即不扩 CLI 契约面，故 `tools/check_contracts.py` 无需新增断言；`--check` 是边界校验入口（承 R5.9）。

`--check` 的签名是 `_check(run_dir: Path)`——**它收不到任何预算 flag**，这直接决定了预算值的记录方式（见 D6）。

## Goals / Non-Goals

**Goals:**

- 让"单元输入 ≤ 预算"这条承诺在 sdr 上**实际成立**，而不是"估算上成立"。
- 超预算时优先做**无损**修复（重切），把有损修复（瘦身）与终止（退出码 2）留给真正无解的原子情形。
- 任何降级都可复核：机器痕迹进产物，人读痕迹进报告边界声明。
- 预算内路径逐字节不变——这是本 change 唯一的无回归判据。

**Non-Goals:**

- 不改默认预算值、不改分组算法（排除过滤器、调用链锚定、跨 controller 拆分、目录聚类规则）。
- 不靠重渲染缩减 diff 上下文（例如改用 `git diff -U0`）——那会改变"证据"的定义面，超出本次修复范围。
- 不动 `-partN` 命名形态与 `chain[]` 随每份续单元携带的既有规则。
- 不把瘦身做成通用机制供其他命令复用（init 侧已有自己的字段分级实现）。

## Decisions

### D1 — 闸门判据 = 渲染后实测字节；测量函数与渲染同源

新增一个模块内的测量函数（形如 `_measure(unit, ...) -> int`），其实现就是"调用 `_render_slice` → `len(text.encode("utf-8"))`"。**绝不**另写一套估算。

理由：这是本 change 的全部价值所在——只要判据仍与产物不同源，"估算 ≤ 预算而渲染 > 预算"就依旧存在。测量复用渲染器同时也保证了"判据漂移"不可能发生：改了渲染就同时改了判据。

备选（未采纳）：① 给估算公式调参（把每文件 64 字节余量调大）——仍是猜测，且会随渲染格式演进而失效；② 物化后测量再补切——那需要为"已写出的切片"设计撤销/重写路径，且中间态会被并发读。

### D2 — 把实测值下沉进既有打包器，而不是在物化后加一道独立的补救流程

`_cluster_standalone` / `_cluster_standalone_sel` / `_con_bytes` / `_split_interface_budget` 判定成员大小时一律改用实测值；`_split_interface_budget` 内"单成分超上限 → 在成分的文件间再切"的分支同样改用实测。

理由：一级修复（无损重切）于是**不是新算法，而是既有贪心规则在正确判据下的自然结果**——多文件单元超预算时，贪心打包本就会把它拆开；原子残渣（单文件）超预算时，`never split mid-file` 规则本就会让它整份留下，恰好就是我们需要的"进入第二级"的判定条件。这避免了第二套切分算法与既有算法漂移。

代价：打包期每个候选都要渲染一次。原 `_size(merged)` 本身已是"每候选重算 Σ 全体成员"（文件数上是二次方），换成本渲染不改变渐进复杂度，只抬高常数因子（渲染是纯字符串拼接，无 I/O、无子进程）；相对同一次运行里的 `git diff` 与 codegraph 探测可忽略。实现时 SHOULD 避免在单次候选比较里重复渲染同一候选。

### D3 — 瘦身面 = 描述性上下文块；证据面清单明示

可截：`ann_ctx`（注解上下文块，含未变更路由方法片段）与 `sym_ctx`（java 残余簇的每文件符号表；每文件已有 40 条上限，但单元素内文件数不设限，这是超大簇的主因）。

不可截（`MUST NOT`）：diff 正文（`fd.hunks[].body`）、"Files in this unit" 清单、每个 hunk 的 `@@ <path> @@ new-file lines N+C` 定位头、`route`/`kind`/`repo`/`diff range` 头部字段。

理由：子代理的复核必须落到 `file + line_hint` 证据上（任务模板明确要求），定位头与正文是它唯一的事实来源；上下文块只是辅助。截断**必须可见**（切片内写 `… (截断:K 行 / 原 N 字节)`），因为 `ann_ctx` 里携带的未变更路由片段是越权面的锚点——子代理看到截断标记后应把该单元的结论标注为上下文受限，而不是当作信息完整。

备选（未采纳）：截 diff 正文——那会让复核产出基于残缺证据的结论，对**安全门禁**而言是假阴性生成器，比直接拒跑更危险。

### D4 — fail-loud 判定前移：先全量在内存渲染判定，再落盘

`_enumerate` 的现有循环是"渲染一个 → 写一个 → 进 pending"。改为两段：先对本次所有待物化单元渲染并测量，收集超预算（含瘦身后仍超）的单元；有则打印 stderr 报告并 `sys.exit(2)`，**不写任何切片、不写 `grouping.json`**；无则照原样落盘。

理由：零副作用是"零派发"的充分条件——`fanout_runner --tier sdr` 对枚举脚本退出 2 原样 `sys.exit(2)`，只要磁盘上没有可消费的待办清单，就不可能有子代理被派出。反过来说，若先写盘再报错，残留的半份 run 目录会诱导下一次 `--resume` 走入不一致状态。

备选（未采纳）：逐单元报错、其余继续派发（"部分评审"）——门禁命令给出部分结论容易被误读为完整结论；且 `pending[]` 语义（本 change 不改它）会变得含混。

### D5 — 不新增 flag；两级瘦身上限为模块常量

调节杆仍是 `--max-standalone-bytes` / `--max-interface-bytes`；`ann_ctx`/`sym_ctx` 的截断上限写成脚本内常量（镜像 init 侧 `_SLIM_FIELD_CAPS` 的取舍），并在注释里写明"真正的杠杆是预算参数，CLI 契约面不扩张"。

理由：承 R5.1——`--help` 即契约面，每加一个 flag 都是随 install 分发的表面积与 `check_contracts` 的维护点。上限本身不是用户关心的旋钮。

### D6 — 披露形态：`grouping.json` 记录预算真值，`--check` 做可选校验

`grouping.json` 顶层新增预算记录（本次生效的两个上限），每个 `pending[]` 项新增 `slimmed`（`{字段名: 原始字节数}`，未截断为 `{}`）。`--check` 在字段**存在**时断言"每项 `unit_bytes` ≤ 其适用上限"与 `slimmed` 结构合法，缺失则跳过。

理由：`_check(run_dir)` 只收 run 目录、收不到预算 flag，所以预算的真值只能由产物自己携带——这也顺带让"用不同 `--max-*` 复核旧 run"这件事有确定语义（以记录值为准）。可选校验是为了向后兼容：`--check` 对旧 `grouping.json` 必须继续退出 0，与既有 `excluded`/`codegraph_stats`/`chain[]` 增量字段的处理同例。

报告侧：`render_sdr_report.py` 的 `_boundaries(...)` 增加一条条件性边界项（仅本次确实发生瘦身时出现），经既有的报告章节与 manifest 双出口披露。注意该函数所在 `--check` 断言 `boundaries` 条目数下限，新增条目是"加"而非"换"，不触碰既有下限。

### D7 — 规格以 ADDED 增量表达，不重述既有长要求

delta 采用 `## ADDED Requirements` 新增「切片物化的字节闸门与超预算三级处置」一条，而不改写 `security-design-review` 中那条约 200 行的既有分组要求。

理由：既有要求**没有**规定判据取估算还是实测（它只说"受字节预算约束、超预算拆续单元"），故新行为与它不冲突；而 `MODIFIED` 要求逐字重述整块内容，200 行的搬运在归档时会把整条要求替换掉，是纯粹的错误引入风险。这是 openspec 指引"新增关注点且不改变既有行为时用 ADDED"的直接适用。

### D8 — 已知的同形冗余：`sym_ctx` 首行的重复标题 MUST NOT 顺手修

`_build_units_callchain` 构造 `sym` 时首行写入 `"## Files & symbols in this cluster (branch version)"`，而 `_render_slice` 在 extend 之前已经写过同一句标题，切片里因此出现两行相同标题。

本 change **不修**它：删掉那一行会让所有含符号表的切片字节数变化，直接破坏"预算内逐字节不变"判据。记录在此，供未来的改变在明确接受该无回归线被重画时处理。

## Risks / Trade-offs

- **闸门收紧后，原本"能跑"的运行可能以退出码 2 终结** → 缓解：一级修复（无损重切）承接全部多文件情形，只有"单个文件的 diff 正文本身超上限"才会终止；stderr recipe 给出显式出口（提高上限 / 收窄 diff 区间 / 单独复核该文件）。这是缺陷修复而非回归——旧行为是把注定超限的请求发出去。
- **打包期渲染抬高常数开销** → 缓解：无 I/O、无子进程，渐进复杂度不变（见 D2）；定向单测记录耗时，不引入墙钟等待。
- **瘦身降低上下文完整度 → 该单元可能漏判** → 缓解：只作用于原子残渣这一狭窄情形；截断在切片内可见，子代理可据此标注结论受限；报告边界声明披露，不静默。
- **测量与物化漂移（两处渲染）** → 缓解：D1 的单函数约束 + 单测断言 `pending[].unit_bytes` 恰等于落地切片文件字节数。
- **字节口径不一致（utf-8 vs 平台默认编码）** → 缓解：一切读取/写入走 `encoding="utf-8"`（承 R5.3a），字节数一律按 `encode("utf-8")` 计；`_render_slice` 结尾统一补换行，测量与落盘同文本。
- **旧 run 目录在新代码下复核** → 缓解：新字段全部可选，`--check` 缺失即跳过；不写任何迁移逻辑。

## Migration Plan

无数据迁移。改动集中在一个确定性脚本与其渲染报告；回滚 = 还原该脚本即可，历史 run 目录无需处理（新增字段对旧代码不可见即为多余字段）。发布面按惯例随 CHANGELOG / VERSION bump 走。
