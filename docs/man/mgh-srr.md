# /mgh-srr 使用说明(人话版)

> 受众:人类。本文件是说给你听的通俗说明;命令的完整技术定义在命令壳 `.md` 里,给 AI 读。

## 这命令做什么

你手上有一份**自由格式的需求文档**(Word、txt、md、Excel,或者直接贴一段文字),想让 AI 从
安全角度审一遍—— `/mgh-srr` 就是干这个的。它不需要你的项目用 openspec,也不要求需求文档
有任何固定格式。

它做的事和 `/mgh-sra` 一样(九个安全维度逐条找缺口、优先建议复用项目里已有的安全措施、
批量向你提问),区别只在两头:输入是「任意格式的需求文档」而不是 openspec 变更,输出是
一份普通的安全评审报告而不是写回变更。中间的分析过程和 `/mgh-sra` 完全同一套,没有任何
偷工减料。

word/excel 这类二进制文档,它会用 Python 自带的能力尽力抽取文字;抽不全的部分会在报告里
标注「降级」提醒你,你也可以用 `--text` 直接贴文字保底。

## 会动你项目里的哪些文件

- **新建** `<你的项目>/.mgh-srr/`:评审过程的中间产物和最终报告。
- **新建/更新** `<你的项目>/.mgh-sra/business_context.json`:和 `/mgh-sra` 共用的项目级
  业务记忆(你回答过的问题在这里累积,两种命令互相受益)。
- **不会**碰 openspec 目录,**不会**改你的需求文档本身,**不会**改你的源代码。

## 产出什么

| 文件 | 是什么 |
|---|---|
| `.mgh-srr/security_review_report.md` | 人读的评审报告(简体中文):按维度列出缺口、可复用的现成措施、待澄清的问题 |
| `.mgh-srr/clarifications.json` | 它问你的问题清单 |
| `.mgh-srr/srr_manifest.json` | 本次运行的统计和边界记录 |
| `<项目>/.mgh-sra/business_context.json` | 项目级业务记忆(与 `/mgh-sra` 同一份,累积复用) |

## 风险与边界(诚实披露)

- **报告是「AI 给的候选意见」,需要人判断采纳**,不是审计结论。
- 只能看到需求文档里**写了的**和你**回答过**的内容;没写的它不猜。
- 引用已有安全措施时,断言「存在」不断言「有效」。
- 二进制文档(word/excel)的文字抽取是尽力而为:格式复杂的表格、嵌入对象可能抽不全,
  报告会标注哪些部分是降级处理的;对准确性要求高就用 `--text` 直接贴纯文本。
